## 二、观察项清零（§2）

1. **向导打开默认流 rowVersion 提示**：**复现并定性=产品缺陷（O-20-5-4，回 20-03 前端会话）**。dev 双程复现（非外测环境特有）：打开既有流后向导**未经任何编辑即自动保存**——`FlowWizardPage` 的 `lastSaved` 指纹未以载入态初始化，首个 autosave effect 必然触发写盘；步位切换改变 state 再触发第二次保存，两发 `flow.updateDraft` 以同一 rowVersion 竞态 → 后者 409 →「版本冲突，请刷新」常驻顶栏。取证：T4 网络监听 `updateDraft` 响应序列 + 冲突文案 + 失败现场截图（`test-failed-1.png` 顶栏「版本冲突，请刷新」）；证据落盘 `D:\tmp\shots-iter20-05\section2-1-evidence.json`。页面渲染与功能本身正常（保存语义未丢数据，同逻辑定义重写），故定级中。**影响面**：凡打开既有流的编辑会话都会白增一次写盘与一次 409 噪音；多页签/多用户并发编辑时误导性强。修复建议：装载完成后以 `[meta, schema, def, flowId]` 载入指纹初始化 `lastSaved`，并在保存中忽略与已存定义等价的写盘。
2. **iter18-02d 并发断言加固**：iter18-acceptance T5 已采用双独立 request context + 8 轮有界重试观测 409（18-05 复验时改写，本棒复核该形态在位）。
