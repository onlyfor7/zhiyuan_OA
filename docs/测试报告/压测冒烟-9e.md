## 三、处置记录（两轮压测的排障留痕）

1. **首轮写路径全 400**：`activityType:"project_work"` 非合法枚举（合法集 professional_work/meeting/travel/quality_review/internal_admin/other）——脚本修复后四段共 12902 请求全 200 真实 delete+insert 事务通过。
2. **projectHealth 多场景连跑出现 ~70% nginx 502**（`connect() failed (99: Address not available)`，v1/v2 均现）：web 容器→server 的 docker NAT 源端口/conntrack 在 9 场景连续 100 连接风暴下累积耗尽——**应用侧同窗口 server 日志显示该端点被成功处理的请求 0–7ms 完成**；单独重跑 100 并发零 502、925 rps（§二 A）定谳为测试基础设施产物。**运维手册建议：压测分段+冷却（脚本已内置 3s），或压测直连 server 端口绕开 web NAT。**
3. **登录风暴段 p97.5=3194ms**：同账号 100 并发同时登录属合成攻击形态（scrypt 有意 CPU 硬，单进程事件循环序列化；§14.4 限流语义=**失败**计数 5 次/分，成功不清零亦不拦截，故风暴段 459 次成功全 200、无限流误伤）。真实 100 用户形态=不同账号+时间分散，标定段 p97.5=189ms 证写 SLO 成立。
4. **首轮 p95 undefined**：autocannon 分位名为 p50/p97_5/p99（无 p90/p95），报告与脚本统一改用 p97.5 保守代理。
