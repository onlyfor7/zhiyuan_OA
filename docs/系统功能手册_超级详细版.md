## 0. 系统总览

### 0.1 定位
面向律师事务所/专业服务机构的业务管理平台，覆盖「市场获客 → 商机立项 → 项目交付 → 经营核算」全链：CRM（线索/商机/客户/合同）、项目全周期（计划/任务/会议/出差/预算/经费/费用/工时/质量/决策/周报/档案/审批流/结项）、协同审批、经营财务（收款/应收/发票/核算）、报表中心、组织治理与 AI 助手「小元」。

### 0.2 角色全景（14 个角色 key）
| 角色 key | 中文名 | 核心职责 | 默认数据范围 |
|---|---|---|---|
| `partner` | 合伙人 | 立项、审批、结项、全局只读 | 全局只读 + 项目内管理权 |
| `project_manager` | 项目负责人 | 项目空间全链管理 | 所负责项目 |
| `member` | 项目成员 | 执行：任务/会议/出差/报销/工时 | 所参与项目 |
| `quality_lead` | 质量负责人 | 质量问题/检查 | 所参与项目质量域 |
| `finance` | 财务 | 收款/费用/核销/支付/核算 | 合同激活后全链财务明细 + 合同前汇总 |
| `archivist` | 档案管理员 | 档案授权审批 | 档案域 |
| `sysadmin` | 系统管理员 | 组织/参数/审计/数据纠正 | 全局最高（写操作受白名单约束） |
| `viewer` | 只读查阅人 | 被授权后只读查看 | 授权范围内 |
| `sales` | 销售 | 线索/商机/跟进/转化 | 仅本人负责 |
| `sales_manager` | 销售主管 | 下级管理、真实性复核 | 本人 + 主管树全部下级 |
| `presales` | 售前 | 被指派商机介入 | 被指派商机及关联对象 |
| `operations` | 运营 | 台账/预测/经营分析 | 全公司台账 |
| `regional_vp` | 大区 VP | 区域销售管理、逐级审批 | 管理树范围 |
| `ceo` | CEO | 重大审批、经营视图 | 全局经营只读 + 审批职责 |

角色可组合（如 合伙人+质量负责人、合伙人+CEO）；数据范围由「角色能力并集 + 主管树递归 + 项目成员表」在 **SQL 层**解析（见 11 章矩阵）。演示账号见《用户自助测试手册》1.2（口令由管理员分发，本册不写）。

### 0.3 导航结构
顶部为八组级联导航：总览 / 客户 / 项目 / 协同 / 经营 / 报表 / 办公 / 治理；每组下挂二级菜单，按角色过滤渲染（无权限的组/项不渲染）。桌面左侧无常驻项目索引（IA v2 起移除），项目先列表后空间。截图：级联导航见 `01-04-cascade-nav.png`。

### 0.4 多页签工作区
页面在顶部以页签形式打开，支持 keep-alive（切回不丢草稿）、关闭其他、恢复；标签条在 375px 下自动隐藏。截图：`01-05-tabs.png`。

### 0.5 移动适配
375 / 390 / 414 三档断点：单列布局、卡片式列表、弹窗全屏化、触控目标 ≥44px、小元宠物可拖拽。截图：`10-01-mobile-projects.png`、`10-02-mobile-dialog.png`。

### 0.6 权限与安全原则（服务端唯一口径）
- 列表/详情/搜索/报表/导出/AI 上下文/小元提醒统一走同一数据范围解析器，禁止只滤菜单或在内存删行。
- 越权详情统一返回 `ACCESS_DENIED_OR_GONE`（同形 404），不泄露存在性。
- 金额/联系人/跟进等敏感字段按 DTO 白名单与形态剥离（如 finance 合同激活前仅汇总、project 形态金额全剥离）。
- 审计日志 append-only：纠正/导出/审批/登录等全留痕，不可篡改删除。
- 全库金额内部按分存储、界面按「元」展示；工时内部按分钟、界面按「小时」展示（0.5 小时步进）。

## 3. CRM 全链

**功能目的：** 市场获客到签单回款的客户资产主线。**入口：** 客户组（线索/商机/客户/合同/跟进）。
**适用角色：** sales / sales_manager / presales / operations / regional_vp / ceo / partner / sysadmin（交付后端角色默认无 CRM 明细权）。

### 3.1 线索池
- **字段：** 名称、来源、联系人/电话（白名单纠正字段=contactName/contactPhone/source）、状态、负责人；**无 LD 编号**（code 可空，UI 不显示编号列）。
- **操作：** 新建（弹窗）、编辑抽屉、写跟进（跟进时间线）、转化 Stepper、作废。
- **状态机：** new → contacted → qualified → converted ；new/contacted/qualified → disqualified。
- **权限：** 销售只见本人；主管见下级树；售前经指派穿透见关联线索。
- 截图：`03-01-leads.png`（列表）、`03-02-lead-drawer.png`（抽屉含跟进区）。

### 3.2 线索转化 Stepper（arch/13 D5 核心）
- **路径：** 抽屉内「转化」→ Stepper：① 客户（名称/等级/行业，或选既有客户）② 商机（名称/预计金额/赢率/负责人必填/售前可选）③ 确认。
- **事务语义：** 同事务建 客户 + 商机 + **项目（MTR/PRJ）** + 项目成员 + 售前计划；商机幂等键重放不重复立项；可「关联既有商机」不新建项目。
- **常见错误：** 负责人必填（400）；同幂等键异载荷 409；越权关联他人商机同形 404。
- 截图：`03-03-lead-convert.png`。

### 3.3 商机
- **视图：** 表格（筛选/排序）与看板（六阶段列，拖拽改阶段）双形态。
- **字段：** 名称、阶段、预计金额（元）、赢率、负责人、售前指派、关联项目/来源线索。
- **状态机（OPPORTUNITY_STAGE）：** initial（初步）→ needs（需求）→ proposal（方案）→ negotiation（谈判）→ won（赢单）/ lost（输单）。
- **赢单：** 同事务建合同（draft 默认；activate=true 则激活）→ 关联项目转 in_progress（见 4.1）。
- **关闭：** markLost（需理由）→ 关联项目同转 closed。
- **权限特例：** 金额按财务可见权形态剥离；售前仅见被指派。
- 截图：`03-04-opps-table.png`、`03-05-opps-board.png`、`03-06-opp-drawer.png`。

### 3.4 客户 / 联系人
- 客户由线索转化产生（无独立新建端点）；客户详情六页签：概况/联系人/商机/合同/项目/往来文件。
- 联系人：多联系人 + 主要联系人互斥（服务端切换）。
- 截图：`03-07-customers.png`、`03-08-customer-contracts.png`。

### 3.5 合同与付款计划
- **状态机（CONTRACT_STATUS）：** draft → active → completed ；draft/active → terminated（终止需理由，审计留痕）。
- **付款计划：** 合同下多计划行（seq/到期日/金额），行状态机 unpaid → partial → paid。
- **回款勾稽：** 收款登记可挂合同+计划行 → 行状态自动写回；作废冲正回写（详见 6.2）。
- **金额口径（D4）：** finance 仅 **active** 合同放行外层+累计+计划行金额；draft/terminated 整体缺席（过滤强于剥离）；pm（project 形态）行可见但金额全剥离。
- 截图：`03-08-customer-contracts.png`（客户详情·合同页签）、`03-09-contracts.png`（合同台账）。

### 3.6 跟进记录
全对象跟进时间线（线索/商机/客户），按目标类型过滤。截图：`03-10-followups.png`。

## 4. 项目全周期

**功能目的：** 商机成交即立项，交付全过程管理到结项。**入口：** 项目组；项目空间 `/projects/:id/:tab`。
**适用角色：** partner（立项/结项/全局）、project_manager（空间全链）、member（执行）、quality_lead（质量）、finance（财务页签）、archivist/viewer（授权）。

### 4.1 商机即立项（D5 生命周期）
- `project.lifecycle_status`：**preparing（售前）→ in_progress（交付）→ closed（已关闭）**。
- 商机赢单 draft：项目不转（仍 preparing）；合同 activate：同项目 id 转 in_progress；商机关闭：同项目 closed；closed 项目阻断费用新增（400/404）。
- 计划两阶段：售前计划（plan_versions baseline）随立项自动生成；交付计划随激活接管。

### 4.2 项目列表与新建
- 列表：关键词/生命周期/健康度筛选，服务端分页（20/页 + 加载更多），「已加载 N 个」计数。
- 新建（partner/sysadmin）：整页向导（F4 例外）：客户与事项 → 模板 → 团队/负责人 → 计划；提交即立项。
- 截图：`04-01-projects.png`、`04-02-project-new.png`。

### 4.4 质量与决策
- 质量问题状态机：open → handling → pending_review → closed；严重度 critical/severe/major/minor；检查项 pending/passed/failed/waived。
- 决策：draft → deciding → decided → verified，关联会议与任务。

## 5. 协同与审批

**功能目的：** 会议/出差/通用申请三类协同对象 + 两级审批引擎。**入口：** 协同组、审批中心 `/approvals`、办公组。

### 5.1 会议全链
- **状态机（MEETING_STATUS）：** planned → completed / cancelled。
- **纪要（MEETING_MINUTES_STATUS）：** none_required → pending_draft → pending_confirm → confirmed；行动项 open → converted（转任务）。
- **权限：** 项目成员可读；组织者/负责人可改；参会人确认考勤（planned/attended/absent/excused）。
- 截图：`04-06-meetings.png`。

### 5.2 出差全链
- **状态机（TRAVEL_STATUS）：** draft → pending_approval → approved → in_progress → completed → closed；分支：rejected、cancelled。
- **变更重审：** 已批出差变更关键字段 → 重新进入审批（travel_change 变更重审全链）。
- **会签：** 支持双人会签（any/all 规则）。
- 截图：`04-07-travel.png`。

### 5.3 通用申请单（办公组）
- 请假/采购/用章等通用审批对象；流程含 initiator_choice 节点时**自选审批人**（UserPicker 关键词过滤）。
- **状态机（GENERIC_REQUEST_STATUS）：** draft → pending_approval → approved / rejected；可 withdraw 撤回。
- 截图：`05-05-generic-request.png`（发起弹窗）。

### 5.4 审批中心与详情快照
- **审批实例状态机（APPROVAL_INSTANCE_STATUS）：** pending → approved / rejected / withdrawn。
- **步骤状态机（APPROVAL_STEP_STATUS）：** pending → approved / rejected / transferred / skipped。
- **业务详情快照：** 审批卡内嵌业务只读快照（报销/出差/申请单三分型），项目名真名，非审批人直开 404。
- 截图：`05-01-approval-center.png`、`05-02-approval-detail.png`。

### 5.5 流程设计器与两级流程
- **节点类型：** start / approval / condition / end；审批人 kind：role / user / initiator_manager / project_manager / initiator_choice；条件字段：amount_cents / confidentiality / level / borrow / request_type。
- **作用域（FLOW_SCOPE）：** global（系统级，/admin 审批流中心维护）与 project（项目级，项目空间 flows 页签维护）；项目流发布后接管绑定业务，停用回退全局流；草稿可深度编辑后发布。
- 截图：`05-03-flow-designer.png`（画布）、`05-04-project-flows.png`、`08-04-admin-flows.png`。

## 6. 经营与财务

**功能目的：** 项目预算经费管控、费用核销、收款应收发票、项目成本核算。**入口：** 经营组、项目空间财务页签、`/fin/*`。
**适用角色：** finance（主操作）、partner（审批）、project_manager（预算/费用发起）、member（报销/申请）、sysadmin（参数/纠正）。

### 6.1 预算
- **状态机（BUDGET_STATUS）：** draft → pending_approval → active → closed；调整产新 active 版本，旧版 **superseded**（版本链可追溯）。
- **控制：** 超预算 block（硬阻断）/ escalate（升级审批）双分支；科目级占用/释放随经费申请与核销联动。
- 截图：`04-08-budget.png`。

### 6.2 经费与收款勾稽
- **经费两态分离：** 审批态（FUNDING_APPROVAL_STATUS：draft/pending_approval/approved/rejected）与使用态（FUNDING_USAGE_STATUS：unused/partially_used/written_off/closed）。
- **收款台账（RECEIPT_STATUS）：** registered → voided（作废冲正，留痕）。
- **勾稽：** 收款挂合同+计划行 → 行状态写回（unpaid→partial/paid）；作废 → 行状态回滚；应收 partial → settled 写回、作废回 open；**不挂合同兼容**（半挂校验：合同与计划行须同给，否则 400）。
- 截图：`06-01-receipts.png`、`04-17-funding-new.png`（经费申请单）。

### 6.3 费用报销
- **状态机（EXPENSE_STATUS）：** draft → pending_approval → rejected；→ approved_pending_payment → paid。
- **规则：** 幂等键防重；重复票据命中/不命中矩阵（主辅因子）；已支付编辑被拒；调整净额可追溯；财务支付动作独立权限。
- 截图：`06-06-expense-check.png`（财务检查视角）、`04-09-expenses.png`（项目费用）。

### 6.4 应收与发票
- **应收（RECEIVABLE_STATUS）：** open → partial → settled；账龄分桶（0-30/31-60/61-90/90+ 天，宽限期参数化）+ 逾期红条。
- **发票（INVOICE_STATUS）：** draft → issued → sent → voided（红冲冲正行，冲正不删行）。
- **生成幂等：** 重复生成零新增；开票联动应收带出，抬头=公司信息。
- 截图：`06-02-receivables.png`（含账龄分桶）、`06-03-invoices.png`。

### 6.5 项目核算与成本率
- 项目核算三段成本：售前成本 / 交付成本 / 总成本（+成本率），与台账/工时抽样重算勾稽一致。
- 成本率等参数为系统参数白名单键（sysadmin 维护）。
- 截图：`06-04-project-costing.png`、`06-05-system-params.png`。

## 13. 异常与常见问题

| 场景 | 界面/提示 | 处理 |
|---|---|---|
| 系统页无权限 | 「没有访问权限 + 角色徽标」（`13-02-no-permission.png`；菜单守卫页同类见 `11-01-member-404.png`） | 联系管理员配置角色；直链撞库同理 |
| 业务对象同形 404 | 「不存在或无权访问」（`13-01-not-found.png`） | 对象不存在或不在数据范围，不泄露存在性 |
| 真 404 | 「页面不存在」（ERROR · 404，路由兜底，`13-03-page-not-found.png`） | 检查链接/路由 |
| 409 冲突 | 「数据已被他人修改，请刷新后重试」（STATE_CONFLICT） | 刷新后重试；数据纠正/并发保存触发 |
| 校验错误 | 字段级红点 + fieldErrors（400） | 按提示修正必填/格式/枚举 |
| 审批阻断 | 必选审批人/上一节点未过/项目 closed 阻断 | 补选人、等审批、或先激活项目 |
| 预算不足 | block（硬阻断）或 escalate（升级审批） | 追加预算/调整科目，或走升级链 |
| 重复票据 | 重复命中拒绝（主辅因子矩阵） | 换票或联系财务人工裁定 |
| AI 不可用 | 403（未启用）/429（限流）/配置缺失 | sysadmin 查 AI 配置与用量 |
| 网络瞬断 | SSE 回退 HTTP 兜底 | 自动恢复，通知延迟到达 |
