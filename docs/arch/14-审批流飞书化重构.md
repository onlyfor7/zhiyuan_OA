## §2 目标形态总览（四步向导）

```
审批管理后台（分组列表）
   └─ 新建/编辑审批 → 向导整页：
        ① 基础信息：图标/名称/说明/分组/谁可以提交/流程管理员
        ② 表单设计：左控件库 + 中手机式预览画布 + 右字段属性（点选配置）
        ③ 流程设计：竖向流程图（提交→〔+〕→节点→〔+〕→结束）+ 节点点击右侧抽屉配置
        ④ 更多设置：提交人权限/审批人去重/标题摘要
        顶栏：返回 / 步骤条 / 预览 / 发布（草稿自动保存）
```

适用两处入口，同一组件两态：
- **系统级**：治理 → 系统配置中心 → 审批流（sysadmin/partner 现行门槛不变）
- **项目级**：项目空间 → 审批流页签（项目负责人现行门槛不变；项目级流程**不做表单设计**（无自定义表单语义），向导减为「基础信息(简)/流程设计/更多设置」三步）

## §3 流程定义模型 v2（definitionJson schemaVersion=2）

竖向序列表（有序数组即流程序），替代 v1 的 nodes+edges 自由图：

```jsonc
{
  "schemaVersion": 2,
  "settings": {                    // 更多设置（§10）
    "allowWithdrawPending": true,  // 允许撤回审批中的申请（映射现有 withdraw）
    "dedupeApprover": "once",      // 审批人去重：once=同一审批人只审一次（后续自动同意）/ always=每节点都审
    "titleTemplate": null,         // 审批标题模板（null=表单名）
    "summaryFieldKeys": []         // 摘要字段（null=前 3 个字段）
  },
  "nodes": [ /* 有序节点数组，详见下 */ ]
}
```

节点类型（`FLOW_NODE_TYPE_V2`）：

| type | 说明 | 关键字段 |
|---|---|---|
| `approval` | 审批节点（橙色卡） | `name`、`approvalType: manual/auto_pass/auto_reject`、`approver`（§6）、`countersign: any/all`、`sameAsInitiator: self/skip/to_manager/to_dept_head`、`ops`（§7）、`fieldPerms`（§9） |
| `condition` | 条件分支（分支列） | `branches: [{ name, expr?, nodes: [...] }]`——`expr` 缺省的最后一条=「其他情况」else 分支；`nodes` 递归子序列 |
| `cc` | 抄送节点 | `name`、`receivers`（审批人策略同构子集） |

- 提交/结束为首尾固定语义节点，不进 nodes 数组；提交节点配置（谁能提交/抄送）在基础信息，结束抄送在最后一个抽屉区。
- **结构强约束**（validate 时强制）：条件分支至少 2 条、else 必须最后、分支内 nodes 可空（=直接通过）；嵌套分支最多 3 层；单流程节点总数 ≤ 100。
- **v1→v2 迁移**：线性链直接映射；v1 condition（when true/false 双边）→ 两分支 condition 节点；画布坐标丢弃；迁移在数据工单以迁移函数完成（纯函数 + 迁移脚本 + 回滚SQL 留底）。

## §4 表单设计器（自定义表单）

### 4.1 数据模型（新增表 `custom_form_defs`）

| 列 | 说明 |
|---|---|
| id uuid PK / code text 唯一（CF-前缀自动编号） | |
| name / description / icon / group_name（分组） | 基础信息 |
| visibility jsonb `{mode: all/roles/users, roleKeys?, userIds?}` | 谁可以提交 |
| form_schema jsonb `{fields:[…]}` + form_version int | 表单定义与版本 |
| flow_id uuid FK → flow_definitions（1:1） | 绑定流程（bizBinding=`custom_form:<code>`） |
| status draft/published/disabled + 审计四件套 + row_version | 生命周期 |

### 4.2 控件库（P1 冻结清单）

单行文本 / 多行文本 / 说明（只读展示）/ 数字 / 金额（分存储）/ 单选 / 多选 / 日期 / 日期区间 / **人员**（UserPicker 复用，值=用户 id，可作条件字段与「表单内联系人」审批人来源）/ 附件（复用 files 上传）。
**P2 缓做**：明细/表格控件（子表）、计算公式、关联审批、定位/收款账户等平台无关控件（不适用于律所域）。

字段属性：key（自动生成可改）/ 标题 / 必填 / 占位提示 / 选项集（选项类）/ 数值范围（数字金额）。

### 4.3 自定义表单实例

- **载体复用** `generic_requests`：+`payload jsonb NULL`（按 form_schema 校验后的字段值）、+`form_id`/`form_version` 快照列；`request_type` = 表单 code。
- 校验：服务端按 form_schema 逐字段校验（类型/必填/选项域/数值范围），非法 400 fieldErrors 落位。
- 展示：申请单详情按 form_schema 渲染只读视图；审批快照区同渲染。
- 列表/搜索/导出：通用申请单列表列=固定核心列+摘要字段；全局搜索索引 title+payload 文本化。

## §5 流程设计器（竖向飞书式）

- **画布**：竖向单列自动排布；节点卡=色条头（类型色）+标题+摘要行；卡间连线上「＋」插入按钮（弹出节点选择：审批/条件分支/抄送）；条件分支渲染为横向分支列（每列头=条件表达式摘要+「其他情况」末列），列内继续竖向节点；分支汇合后回到主干。
- **节点操作**：点卡→右侧抽屉配置（随类型不同，§6/§7/§9）；卡上 hover 浮现删除；条件分支列头可增删分支、拖拽调序（else 恒最后）。
- **缩放**：左下缩放控件（沿用现有画布控件样式）。
- **校验**：保存=结构校验（FLOW_INVALID 400，字段级落位到抽屉）；发布=语义校验（FLOW_UNPUBLISHABLE 412：审批人解析为空/条件字段非法等）。沿用现有两阶段语义。
- **旧画布下线**：`FlowDesignerPage.tsx` 画布实现删除，路由 `/admin/flows/:id` 与 `/flows/p/:projectId/:flowId` 指向新向导页；FlowProgressGraph（审批详情只读进度图）**保留**并按 v2 结构适配渲染。

## §6 审批人策略（FLOW_APPROVER_KIND 扩展）

现有 5 种保留：`role` / `user` / `initiator_manager`（直属上级）/ `project_manager` / `initiator_choice`（提交人自选）。
新增：

| kind | 语义 | 依赖 |
|---|---|---|
| `initiator_self` | 提交人本人（配合 sameAsInitiator 的相反场景与特殊流程） | 无 |
| `dept_head` | 提交人所在部门负责人 | org_units.leader_id（18-01 已就位） |
| `manager_chain` | 连续多级上级：`{levels: n}` 沿 manager_id 树向上 n 级，逐级各为一步 | manager_id 树（18-01） |
| `form_contact` | 表单内联系人（仅自定义表单：`{fieldKey}` 取人员控件值） | §4.2 人员控件 |

不做：用户组（无此概念）、节点审批人互引、连续多级部门负责人（用 manager_chain 覆盖）。
「提交人自选」增强：选择范围=全员/指定角色/指定成员（现仅全员）。
**sameAsInitiator**（审批人=提交人时）：self=本人照审 / skip=自动跳过 / to_manager=转直属上级 / to_dept_head=转部门负责人。默认 skip。

## §7 节点操作权限（ops）

| 配置 | 默认 | 语义 |
|---|---|---|
| `transfer`（允许转交） | true | 映射现有转交能力 |
| `returnBack: none/prev/initiator` | none | 退回：上一节点/直接退回提交人（区别驳回=终态拒绝）；引擎=步骤指针回拨，留痕 |
| `requireCommentOnReject` | true | 驳回必填意见（现行为即如此，固化默认） |
| `requireCommentOnApprove` | false | 通过必填意见 |

不做：手写签名、加减签（运行时改链，复杂度高，P2 再议）。
**auto_pass/auto_reject**：引擎到步即自动以系统名义通过/拒绝（留痕 actor=system），用于「条件满足免审」等场景。

## §8 抄送（cc）

- 节点抄送：流程中 cc 节点（到步即通知）+ 提交时抄送 + 结束时抄送（基础信息/结束节点配置）。
- 通道：复用 notifications（站内 + 小元 feed）；接收人策略=角色/指定成员/直属上级/部门负责人。
- 抄送只读权限：实例详情对抄送人开只读（不含操作按钮）；审计记录 cc 事件。

## §9 表单权限矩阵（fieldPerms）

- 粒度：节点 × 字段 × {read / edit / hidden}；默认=该节点 read（审批人视角只读）。
- **自定义表单**：全字段入矩阵（字段来自 form_schema）。
- **固定业务表单**（报销/经费/出差等）：白名单字段入矩阵（各业务给固定可枚举字段清单，如报销的 amount/类别/事由）；edit 语义仅对「退回后提交人修改+审批中补充」场景开放——**P1 只落地 read/hidden**，edit 暂不支持（防业务一致性破坏），UI 上 edit 列对固定表单置灰并提示。
- 运行时：审批详情/实例详情按当前用户所处节点过滤字段渲染；hidden 字段不进序列化输出。

## §10 更多设置（settings，P1 子集）

| 项 | P1 | 说明 |
|---|---|---|
| 允许撤回审批中的申请 | ✅ | 映射现有 withdraw |
| 允许撤回 N 天内已通过的审批 | ❌ P2 | 涉及业务回滚 |
| 审批人去重 once/always | ✅ | once=同人后续节点自动同意 |
| 审批标题=表单名 / 摘要=前 3 字段 | ✅ | 固定规则，先不做自定义模板 |
| 效率统计/打印模板/转发设置/限时审批/自动化 | ❌ | 平台外或无谓义 |

## §11 审批管理后台（系统级）

- 列表改分组形态：固定组「业务审批」（现有 bizBinding 各流程：报销/经费/出差/申请单默认/延期/档案授权…）+ 自定义分组（用户可建组，custom_form_defs.group_name 聚合）。
- 行操作：编辑（进向导）/启停/删除（仅草稿可删）/复制为新草稿。
- 新建入口：「新建自定义审批」（走四步向导，产 custom_form_defs + flow_definitions）；「新建业务流程」=现有语义（给既有 bizBinding 配自定义流，向导三步，无表单设计步）。

## §12 兼容与迁移

1. **存量流程**：全部 v1→v2 迁移（数据工单迁移脚本）；迁移后 enabled 态/版本号保持不变；迁移报告逐流程回执。
2. **在途实例**：policy_snapshot 已物化步骤，不受定义迁移影响——继续走旧步骤到终态。
3. **引擎**：编译器支持 v1/v2 双读（v1 只读兼容，不再新写）；运行时步骤结构加列（退回/自动/抄送/去重所需），对在途步骤默认兼容。
4. **项目模板实例化**（createProjectFromTemplate 拷贝项目流）：随 v2 迁移一并处理模板内嵌定义。
5. **旧画布组件删除**；E4 回退（无自定义流程时 approval_policies）不变。

## §13 权限与审计

- 流程/表单管理：系统级=sysadmin+partner（不变）；项目级=项目负责人（不变）；**流程管理员**=sysadmin（基础信息字段承载语义=管理者展示，不加新权限点）。
- 自定义表单提交权限：visibility 过滤（发起入口按此渲染，服务端校验同形）。
- 审计：表单/流程的建改删发布启停全量审计（沿用 authedMutation）；抄送/自动通过/退回/去重命中均落实例步骤留痕。

## §14 验收标准（概要，验收工单细化）

1. 四步向导全链：新建自定义审批（控件全类型）→ 发布 → member 发起 → 审批人审批（转交/退回/驳回必填）→ 抄送到达 → 完成态。
2. 竖向设计器：＋插入/抽屉配置/条件分支列（≥3 分支含 else）/嵌套一层/删除/调序；保存 400 与发布 412 各有实锤用例。
3. 审批人新策略：dept_head/manager_chain(2 级)/initiator_self/form_contact 四种各一条跑通；sameAsInitiator 四形态。
4. 迁移：存量全部流程 v1→v2 后在设计器打开渲染一致、引擎对在途+新实例行为不变（e2e 回归全绿）。
5. 旧画布路由与组件移除；项目级向导三步形态。
6. 手册同步（常驻规则）：两册更新+截图重拍。

## §16 风险与开放项

- 表单设计器+引擎扩展为项目迄今最大单迭代；20-03 前端体量最大，若超预期允许按基线再切（先竖向设计器+固定表单，自定义表单其次）——由架构在 20-02 验收时评估决定。
- 明细表格控件（子表）影响 form_schema 与运行时渲染深度，P2。
- 飞书「审批人离职自动转交上级」与我们「停用即会话失效」口径不同：我们的离职=停用账号，审批人解析时空用户 → 发布 412 拦截；在途实例遇审批人停用 → 由 sysadmin 数据纠正/转交处置（本期不做自动转交）。
