## 2. 数据模型细案（7 张新表）

通用字段沿用 arch/01 §2；金额一律 `amount_cents bigint`（drizzle bigint mode:'number'）；前缀 `BUD/FND/EXP/LED` 已注册。

- `budgets`：project_id FK, code(BUD), version_no int, period_start/end date, currency text default 'CNY', total_cents bigint, description null, status `budget_status`(draft/pending_approval/active/superseded/closed), approval_instance_id FK null, 四件套+row_version。unique(project_id, version_no)；**每项目恰一个 active**（部分唯一索引，同 plan_versions）。
- `budget_categories`：budget_id FK, category `expense_category`（arch/02 §3.1 八值落 pgEnum）, amount_cents bigint, unique(budget_id, category)。可选：无类别行 = 只控总额（统计口径不得误判为零预算）。
- `funding_requests`：project_id FK, code(FND), applicant_id FK, purpose text, amount_cents bigint >0, expected_use_date date null, recipient_info text null（收款/借款说明）, source_meeting_id/travel_id FK null, approval_status text（draft/pending_approval/approved/rejected，引擎驱动）, usage_status `funding_usage_status`(unused/partially_used/written_off/closed), approval_instance_id FK null, closed_at null, close_note null, 四件套+row_version。**审批态与使用态分离**（基线 §9）。
- `expense_reports`：code(EXP), applicant_id FK, reason text, is_cross_project bool default false, travel_id FK null, meeting_id FK null, total_cents bigint not null（**服务端由明细计算，前端传入忽略**）, status `expense_status`(draft/pending_approval/rejected/approved_pending_payment/paid), approval_instance_id FK null, paid_at/by null, payment_ref null, 四件套+row_version。单头项目归属以明细为准——**不写 project_id 列**（明细级归属，EXP-001）。
- `expense_items`：expense_report_id FK, project_id FK（明细级，跨项目拆分逐行鉴权）, funding_request_id FK null, date date, category `expense_category`, amount_cents bigint >0, description text, payee null, receipt_no text null（票据代码号码）, receipt_file_version_id FK null, receipt_satisfied bool（写入时按类别规则计算）, 四件套。
- `budget_ledger`：code(LED), project_id FK, budget_version_id FK null, source_type, source_id, entry_type `ledger_entry_type`（arch/01 §4 六值）, reserved_delta_cents bigint default 0, actual_delta_cents bigint default 0, occurred_at timestamptz, **idempotency_key text unique not null**, created_at。**只追加**；ORM 无 update/delete 路径（同 audit_events）。
- `expense_adjustments`：expense_report_id FK, code?（复用 EXP 前缀不强制）, delta_cents bigint（可负）, reason text not null, approval_instance_id FK null（走引擎）, status text(pending_approval/approved/rejected), created 四件套。已支付记录更正的唯一通道（EXP-009/013）。

## 3. 状态机（冻结）

| 对象 | 迁移 | 硬限制 |
|---|---|---|
| 预算 | draft → pending_approval → active → closed；active →（调整产新 draft 版本→pending→active，旧版 superseded） | active 版本不可改内容；无 active 预算的项目显示「未设预算」≠ 余额零 |
| 经费申请 | 审批态 draft→pending→approved/rejected；使用态 unused→partially_used→written_off→closed | 两态分离；存在未决报销（pending）不得关闭；关闭前系统列出检查项 |
| 费用报销 | draft → pending_approval → rejected / approved_pending_payment → paid；pending → draft（撤回） | paid 后不可编辑/删除；更正只能 expense_adjustments |
| 调整单 | pending_approval → approved/rejected | 通过同事务写 EXPENSE_ADJUSTED 台账 |

## 4. 台账核心规则（逐字执行，arch/01 §4 公式不变）

1. **唯一写入者**：台账只能经 `services/ledger/record.ts` 写入；每条分录带幂等键 `entryType:sourceId:seq`（如 `FUNDING_RESERVED:<fundingId>:0`），唯一约束兜底；重试/重放返回已存在分录。
2. **经费获批**（引擎 handler，同事务）：usage 不动；写 `FUNDING_RESERVED`（reserved_delta=+金额）；通知申请人。
3. **报销获批核销**（同事务，EXP-007 裁定链）：对每条关联经费的明细——按核销额写 `FUNDING_RELEASED`（reserved_delta=−核销额）+ `EXPENSE_RECOGNIZED`（actual_delta=+批准额）；**报销总额超出原占用部分仍记实际支出**并触发超预算检查；禁止双扣（同一金额不得同时占用与实际）。
4. **超预算策略**（BUD-005）：检查结果（可用额度=有效预算−有效占用−实际支出）为负时按 `budget.insufficient_policy`（block/escalate，默认 escalate）：block → `BUDGET_EXCEEDED` 拒绝；escalate → 审批链追加管理层步骤。策略命中原因写审批快照。
5. **统计口径**：实际支出 = Σ EXPENSE_RECOGNIZED + Σ EXPENSE_ADJUSTED（净额）；已支付不重复计；草稿/待审批/已驳回单列。有效工时同理（迭代 4）。
6. **无预算项目**：summary 返回 `hasBudget: false`，前端显示「未设预算」。

## 5. 重复票据与审批检查（EXP-005/006）

- **重复票据**：同一 `receipt_no` + 同金额 +（若有）同文件 sha256 → 命中即 `DUPLICATE_RECEIPT` 阻止并在错误数据中带原报销定位（code/id）；不得依赖文件名。规则与阈值在 `expense.receipt_rules` 配置。
- **审批检查项**（提交报销时服务端计算，随审批快照保存）：预算充足性、经费余额充足性、票据完整性（类别规则）、出差/会议关联存在性、重复票据。每项 {name, pass, detail}；审批人可见。

## 6. 审批策略种子（迭代 3）

| biz_type | match | steps |
|---|---|---|
| budget | 默认 | [partner] |
| funding | 默认 | [project_manager] |

| expense | 默认 | [project_manager] → [finance] |

## 7. API 契约清单（形态沿用 arch/02）

| 域 | 过程 |
|---|---|
| budget | `list {projectId?, cursor}`、`getById`（含类别行与台账聚合：有效预算/有效占用/实际支出/可用额度/执行率 + hasBudget 标记）、`create`（含 categories[]）、`submit/withdraw`、`adjust {id, deltaCents, reason, idempotencyKey}`（产新版本走审批）、`close {id}`、`ledger {budgetId?, projectId?, cursor}`（台账明细，下钻） |
| funding | `list {projectId?\|mine\|status}`、`getById`（已获批/已关联费用/已核销/未使用四数可台账重算）、`create`、`update(draft)`、`submit/withdraw`、`close {id, note}`（检查项列出+未决报销阻断）、`releaseUnused {id}`（关闭未使用部分 → RELEASED） |
| expense | `list {projectId?\|mine\|status\|category\|dateFrom/To}`、`getById`（明细+检查项+审批快照）、`create`（含 items[]，服务端算合计）、`update(draft)`、`submit {id, row_version, idempotencyKey}`（跑 §5 检查项+重复票据）、`withdraw`、`addItem/removeItem`（draft）、`attachReceipt {itemId, fileVersionId}` |
| expense.pay | `markPaid {id, paymentRef, idempotencyKey}`（finance 角色；支付日期=服务端时间）、调整：`adjustCreate {expenseId, deltaCents, reason}`、`adjust` 走引擎 |
| expense.stats | `byProject {projectId, from?, to?}`、`byCategory/byPerson`（状态口径标注 asOf+statusScope）、`exportCsv {filters}`（服务端生成、权限过滤、审计记录导出事件） |

权限：预算/费用汇总默认仅 pm（本项目）/partner/finance 可见；成员只见本人报销（mine）与本人经费；财务不因此获得法律文书内容权（arch/03 §4.3）；票据附件继承费用权限（canReadFile 增 expense 来源分支）。项目密级沿用。

## 8. 集成点（本迭代接通）

- 项目空间「预算经费」「费用」页签真实数据；项目总览加预算执行摘要（可下钻台账）。
- 工作台 todo 增：待我审的经费/费用/预算调整（经 approval 源已覆盖）+ 我的申请状态卡（funding/expense mine 摘要）。
- 驾驶舱 summary 增预算执行率/实际费用（角色范围过滤，高敏金额按密级脱敏）。
- 周报 generateDraft 增费用节（本周已批准报销额/笔数，来源可溯）。
- 归档：经费获批 → archive.link 目录 11；报销获批（含票据）→ 目录 10；导出文件不归档。
- 出差完成页「报销入口」真实接通：expense.create 预填 travelId/行程信息。
- 通知：budget_exceeded（超预算命中，pm+财务+超阈值进管理层待办）；funding/expense 审批结果走通用 approval_result（无专属事件，与迭代 2 裁定一致）。
