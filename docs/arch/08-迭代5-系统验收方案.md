## 3. 安全测试矩阵（§17.1，测试棒）

篡改项目 ID / 用户 ID / 审批人 / 金额 / 文件键 / 分享地址、直链越权、枚举注入、SQL 注入探针（参数化全覆盖）、上传类型/大小绕过、会话固定与过期、停用账号、CSRF（SameSite=Lax + 无 JSON CSRF 面）评估。全部给出用例与证据。

## 4. 性能与可用性冒烟（§14.3，测试棒+部署棒）

- 约定数据量（种子全量 + 脚本扩充至：项目 20、任务 800、工时明细 5000、台账 2000）下，95% 常用查询（列表/详情/统计）< 2 秒（实测记录 p50/p95）。
- 甘特 1000 项任务虚拟化展示流畅性（Chrome 性能探针，无长任务阻塞 >1s）。
- 冷启动：全新 clone → compose up → migrate → seed → 登录可用，全程计时与文档化。

## 5. 生产构建与部署形态（部署棒，裁定）

- **server 生产构建**：esbuild 打包 `server/src/index.ts` → `dist/index.js` 单文件（`@lexflow/shared` 一并打入；pg 等原生依赖 external）。`server/package.json` 的 `build` 由 `tsc --noEmit` 替换为真构建（arch/00 §2 v1.1 的占位语义至此兑现），新增 `start: node dist/index.js`。typecheck 门保留。
- **app 生产构建**：既有 `vite build` → 静态产物；生产由 nginx 服务 + 反代 `/trpc`、`/files` 到 server。
- **生产编排**：`docker-compose.prod.yml`（postgres:16 + server + web 三服务，健康检查，命名卷，环境变量注入）；开发 `docker-compose.yml` 不动。
- **备份恢复**：`pg_dump` 备份脚本 + 恢复演练脚本（台账/审计/文件元数据恢复后校验行数与 sha256），文档化 RPO/RTO 目标（开发期：每日备份、恢复演练通过）。
- 密钥管理：`.env.production.example` 模板；禁止真密钥入库；SESSION_SECRET 生成指引。

## 7. 种子刷新与试用剧本（01 数据 + 05 测试）
