# 架构基线 01 · 数据模型与状态机

**裁定方：** 架构会话　**依据：** 需求基线 V2.0 §4/§6/§8/§9/§10　**状态：** 已冻结（迭代 0 期间）
**说明：** 表名为逻辑名（snake_case 实现），字段列表为最低要求，数据会话可补充辅助列与索引，但**不得丢失关系、历史和权限语义**，不得删改已裁定字段的语义。新增实体/改状态机必须架构会话确认。

## 2. 通用字段（所有核心实体）

```text
id uuid PK default gen_random_uuid()
code text unique                -- 业务编号（见 arch/00 §3.5）
project_id uuid FK projects     -- 允许为空的表：users/org/roles/system_config/code_sequences/
                                --   approval_policies/sessions/file_objects(按来源继承)/notifications
status / 各状态机枚举            -- 受控状态机，禁止自由文本
created_by uuid FK users, created_at timestamptz default now()
updated_by uuid FK users, updated_at timestamptz default now()
row_version integer not null default 0
-- 必要时：confidentiality_level、submitted_at、approved_at、archived_at
```

枚举统一在 `shared/enums/` 定义，DB 用 `text` + check 约束或 pg enum——**裁定为 pg enum**（drizzle `pgEnum`），枚举值变更走迁移。

## 3. 状态机（冻结，与基线 §9 一致）

| 对象 | 状态流（→ 为允许迁移） | 硬限制 |
|---|---|---|
| 项目 lifecycle | 筹备中 → 进行中 → 已结项；健康度独立：正常/预警/风险 | 生命周期与健康度分离；已结项默认只读 |
| 会议 | planned → completed；planned → cancelled | 会议状态与纪要状态分离；取消不生成工时 |
| 会议纪要 | none_required → pending_draft → pending_confirm → confirmed | 确认后修改产生新版本，不覆盖；行动项记录纪要版本 |
| 出差 | draft → pending_approval → approved/rejected → in_progress → completed → closed；pending_approval → draft(撤回)；approved → cancelled | 关键字段变更重新审批；完成 ≠ 费用已批准 |
| 预算 | draft → pending_approval → active → closed | 调整生成新版本；active 版本不可覆盖 |
| 经费申请 | 审批态：draft → pending_approval → approved/rejected；使用态：unused → partially_used → written_off → closed | 两态分离；存在未决报销不得关闭 |
| 费用报销 | draft → pending_approval → rejected/approved_pending_payment → paid；pending → draft(撤回) | 驳回重提保留历史；paid 后只能调整/冲销 |
| 工时周期 | draft → pending_approval → approved/returned → locked | 批准后改动须退回或解锁；全动作留痕 |
| 档案授权 | pending_approval → active → expired/revoked | 到期/撤销即时失效，不默认续期 |
| 审批实例 | pending → approved/rejected/withdrawn（步骤级 countersign 规则见 arch/03） | 同一实例不得出现两个终态 |
| 计划版本 | v1(baseline) 不可变；变更产生 v2/v3… | 历史版本可查看；基线不可覆盖 |

## 4. 台账与统计不变量（预算/费用领域核心，迭代 3 落地，此处冻结口径）

`budget_ledger` 分录类型：`BUDGET_ACTIVATED / BUDGET_ADJUSTED / FUNDING_RESERVED / FUNDING_RELEASED / EXPENSE_RECOGNIZED / EXPENSE_ADJUSTED`。

每条分录：`project_id, budget_version_id, source_type, source_id, entry_type, reserved_delta_cents, actual_delta_cents, occurred_at, idempotency_key (unique)`。

```text
有效预算   = 当前 active 预算版本总额（含已批准调整）
有效占用   = Σ 未释放 FUNDING_RESERVED 净额
实际支出   = Σ EXPENSE_RECOGNIZED + Σ EXPENSE_ADJUSTED（已批准净额）
可用额度   = 有效预算 − 有效占用 − 实际支出
预算执行率 = 实际支出 ÷ 有效预算；无预算项目显示「未设预算」，不得显示「余额为零」
```

报销核销经费时，**同一事务**内：按核销额释放占用 + 记录实际支出；超额部分进实际支出并触发超预算检查；禁止「占用」与「实际」重复扣减同一金额。同一审批重试由幂等键保证只记一次账。

工时统计口径：有效工时 = 已批准+已锁定；草稿/待审批/已退回单列；会议/出差预填与复制草稿不计入。费用统计口径：实际支出默认含已批准及之后状态；已支付是资金状态，不重复计。

## 5. 删除与历史规则

- 草稿：权限内可删除/作废；已提交：撤回；已审批/已支付/已归档/已锁定：**禁止物理删除**。
- 审计与台账不因业务对象作废而删除。
- 版本化对象（纪要、预算、计划、周报、文件）用版本表/版本链，禁止原地 UPDATE 覆盖历史行。

## 6. 索引与约束基线

- 所有 `code`、`idempotency_key`、`token_hash`、（`file_versions.sha256` + 金额，用于重复票据检查）建唯一/普通索引。
- 高频过滤列建索引：`project_id`、`status`、`created_at`、`recipient_id + read_at`（通知）、`actor_id + created_at`（审计）。
- 跨项目对象（跨项目报销）必须明细级 `project_id`，禁止隐式共享。
- 外键全部显式声明；`ON DELETE RESTRICT` 为默认（呼应 §5 删除规则）。
