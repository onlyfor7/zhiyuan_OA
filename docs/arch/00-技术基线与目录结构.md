# 架构基线 00 · 技术基线与目录结构

**裁定方：** 架构会话　**生效日期：** 2026-10-26　**状态：** 已冻结（迭代 0 期间）
**约束对象：** 全部会话。任何偏离必须先在 `docs/STATUS.md` 的「偏差与仲裁」登记并由架构会话确认；导致数据模型返工的冲突必须暂停上报。

## 1. 技术栈（已裁定）

| 层 | 选型 | 说明与约束 |
|---|---|---|
| 前端 | React 19 + TypeScript + Vite 7（现有 `app/`） | 保留 `App.css` 设计系统、三区布局、甘特视觉、Lucide 图标；不重做视觉方向 |
| 前端路由 | react-router 7（已在依赖中） | 真实路由：详情直链、刷新恢复、浏览器返回、权限拦截、筛选状态保留 |
| 前端数据层 | @trpc/client ^11 + @trpc/tanstack-react-query ^11 + @tanstack/react-query ^5 | 唯一数据获取通道；禁止 `useState` 承载业务数据 |
| 服务端 | Hono 4 + @hono/trpc-server + @trpc/server ^11 | 业务 API 走 tRPC；文件上传/下载/预览走 Hono 原生路由（二进制不走 tRPC） |
| ORM / 迁移 | drizzle-orm + drizzle-kit | 全部结构变更必须走迁移文件；禁止手工改库 |
| 数据库 | PostgreSQL 16（开发期由根目录 docker-compose 提供） | 已确认不用 SQLite；schema 写法保持可移植 |
| 共享包 | `shared/`：枚举、类型、zod 校验、常量、错误码 | 前后端唯一公共真相，契约即代码 |
| 认证 | 数据库会话（不透明 token + httpOnly Cookie），scrypt 口令散列 | 不用 JWT（要求可撤销、账号启停即时生效）；预留 SSO 身份映射 |
| 文件存储 | 开发期本地受控目录 `server/storage/`，DB 仅存元数据+校验值 | 提供短期授权访问端点；禁止永久公开地址；部署期可切换对象存储 |
| 测试 | Vitest（单元+集成）；Playwright 留给迭代 5 E2E | 集成测试直连 Hono `app.request`，不引 supertest |
| 包管理 | npm workspaces | 单一根 lockfile；删除 `app/package-lock.json` |
| 运行环境 | Node ≥ 20（当前环境 v24） | typescript ~5.9，zod ^4，pg ^8 |

## 3. 横切铁律（所有会话共同遵守）

1. **金额**：整数「分」，DB 用 `bigint`（drizzle `bigint({ mode: 'number' })`），API 字段命名 `amountCents`。禁止浮点、禁止前端提交可信合计（合计由服务端算）。
2. **工时**：整数「分钟」，`durationMinutes`。禁止浮点小时累加。
3. **时间**：DB 一律 `timestamptz` 存 UTC；纯日期用 `date`。展示默认 `Asia/Shanghai`。跨日会议/出差不得按日期字符串计算时长。
4. **主键**：`uuid`，DB 默认 `gen_random_uuid()`。
5. **业务编号**：`code`，格式 `前缀-年份-五位序号`（如 `MTG-2026-00042`），由服务端用序列表生成；编号不得含客户/项目名称。前缀注册表见 `shared/constants.ts`：`MTG TRV BUD FND EXP TS APR LED PRJ TSK QLT DEC RPT CLT MTR`（CLT 客户、MTR 事项——2026-10-26 v1.1 增补，arch/01 要求客户/事项持唯一 code）`CHG STG MLS DLV`（2026-10-27 v1.2 增补：延期申请/阶段/里程碑/交付物，arch/04 §2）。
6. **乐观锁**：核心表均有 `row_version integer not null default 0`；更新/删除/审批动作必须携带原 `row_version`，不匹配返回 `CONFLICT`，前端保留用户输入并提示刷新。
7. **幂等**：所有创建类与审批类 mutation 接受 `idempotencyKey`（客户端生成的 uuid）；服务端对 `(procedure, idempotencyKey)` 唯一约束，重放返回首次结果，不得重复建行或重复记账。
8. **不可覆盖**：已审批/已支付/已归档/已锁定记录禁止物理删除和原地覆盖；通过新版本、冲销、调整、解锁审批保留历史（基线 §4.2.5、§9）。
9. **台账与审计**：`budget_ledger` 与 `audit_events` 只追加，禁止 UPDATE/DELETE（DB 层面撤销业务角色的写权限或加触发器，至少做到 ORM 层无更新路径）。
10. **单一事实源**：同一业务对象全库一条主记录；任务/行动项/审批/通知/审计通过 `source_type` + `source_id` 关联来源，不各建一套。
11. **事务**：审批通过与业务写入、台账、通知、审计必须在同一 DB 事务完成；做不到的环节（如外部通知）走可靠任务表，界面显示「处理中」而非假成功。
12. **权限**：服务端强制（见 arch/03）；无权限响应统一为不可见语义，不得泄露对象是否存在。
13. **禁止事项**（基线 §19 摘要，触碰即返工）：Toast 冒充成功；隐藏按钮代替服务端校验；本地状态当数据库；硬编码统计；越权角色自动获得内容权限；范围蔓延到计费/薪酬/总账/真实支付。

## 4. 认证与会话（迭代 0 实现）

- 登录：`email + password`，scrypt 校验（`node:crypto`，无原生依赖）；失败统一提示，不区分账号不存在/口令错误。
- 会话：登录成功写入 `sessions` 表（token 散列、user_id、过期时间、创建 IP），Set-Cookie `lexflow_session`，`HttpOnly; SameSite=Lax; Path=/`（开发期不要求 Secure）。默认有效期 8 小时，可配置。
- 中间件：每个 tRPC 请求解析 cookie → 加载用户与角色 → 注入 `ctx.user`；无效/过期返回 `UNAUTHORIZED`。账号停用后其会话立即失效。
- 登出 = 立即使会话失效（`expires_at` 置为当前时间）；**会话行不物理删除**——`audit_events.session_id` 长期引用（ON DELETE RESTRICT），物理删除必然失败（v1.1，2026-10-26 裁定，登记于 STATUS「偏差与仲裁」）。过期会话行的定期清理属运维任务（迭代 5 部署会话）。口令散列不得出现在任何 API 响应与日志中。
- SSO 预留：`users` 表保留 `external_id` 可空列与注释，迭代 0 不实现 SSO。

## 5. 文件存储（迭代 0 实现）

- 物理内容写入 `STORAGE_DIR`（默认 `server/storage/`），存储键 = `uuid + 原始扩展名白名单校验`，禁止路径穿越。
- DB 保存：`file_objects`（逻辑文件）+ `file_versions`（版本、大小、MIME、sha256、上传人、业务日期、密级）。
- 访问：仅经 `GET /files/:fileVersionId/download|preview`，服务端鉴权（来源对象权限 + AccessGrant），可签发 ≤15 分钟短期下载令牌；响应 `Cache-Control: private, no-store`。
- 上传限制：类型/大小/扩展名白名单（pdf、png、jpg、docx、xlsx、zip，单文件 ≤ 20MB，可配置）；上传中失败不得在界面上显示已归档。

## 6. 统一错误处理

- tRPC 错误码映射见契约 arch/02 §6；`shared/errors.ts` 定义业务错误码常量。
- 未捕获异常 → `INTERNAL_SERVER_ERROR`，响应不含堆栈；服务端日志含 requestId。
- zod 校验失败 → `BAD_REQUEST`，`cause` 携带字段级错误供表单映射。
- 权限失败 → 列表静默过滤；详情/直链统一返回 `NOT_FOUND` 形态（不泄露存在性，见 arch/03 §5）。

## 7. 配置与环境

- 仅 `.env`（不入库）+ `.env.example`（入库）。键：`DATABASE_URL`、`SESSION_SECRET`、`STORAGE_DIR`、`PORT`（默认 3001）、`SESSION_TTL_HOURS`（默认 8）。
- 业务默认配置（基线 §18：纪要期限、报销提醒、预算策略、工时周期等）落 `system_config` 表（数据会话建表，键值+JSON），种子写入默认值；代码引用配置键，不散落硬编码。

## 8. 种子数据原则

全部虚构（基线 §14.2）；至少含：1 个组织、8 种角色、≥10 个用户（含迭代 0 验收要求的两个权限差异账号 `pm@lexflow.demo` / `member@lexflow.demo`，口令统一 `Demo@2026`）、2 客户、2 事项、3 项目（含不同密级与成员差异）。迭代 0 种子只建地基数据，业务种子随各迭代扩充。

## 9. 构建与质量门

每个迭代交付前必须通过：`npm run typecheck`、`npm run build`、`npm run test`、`npm run db:migrate`（干净库重放）。命令不存在等于迭代未完成的信号，缺哪个补哪个。
