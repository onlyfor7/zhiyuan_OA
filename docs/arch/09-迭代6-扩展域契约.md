## 2. R 域 · 客户收款登记台账

**边界（裁定）：** 只做「收款登记与台账」——登记到账、关联项目与客户、核销口径（项目应收 vs 实收由收款记录聚合，无独立应收账单实体）；**不做**账单开具、发票、在线支付、自动对账、回款计划提醒（提醒可入通知事件但本期不做）。

### 数据模型

- `payment_receipts`：id, code（新前缀 `RCV`）, project_id FK, client_id FK（写入时按项目冗余，报表口径一致）, amount_cents bigint >0, received_on date, reference_no text（银行回单/流水号）, payer_name null, note null, attachment_file_version_id FK null, status `receipt_status`(registered/voided), void_reason null, voided_by/at null, 四件套+row_version。
- **不可覆盖**：registered 记录金额不可编辑；更正 = void（理由必填+审计）+ 新登记；void 不删行。
- 视图口径：项目实收 = Σ registered − Σ voided（原额）；`receipts.summary byProject/byClient/byPeriod`；驾驶舱/项目总览接入（角色范围过滤）。
- 权限：finance 登记/作废；partner 按范围可见；pm 可见本项目合计与明细；member/viewer 不可见。附件继承财务权限。

### API

`receipt.list {projectId?|clientId?|from/to, cursor}`、`getById`、`create {…, idempotencyKey}`（finance）、`void {id, reason}`（finance，审计）、`summary {by, from?, to?}`、`exportCsv`（审计）。

## 3. F 域 · 审批流自定义（统一引擎 + 通用申请单）

### 3.1 流程定义（可视化配置的落点）

- `flow_definitions`：id, name, scope `flow_scope`(global/project), biz_binding text（现有 biz_type 之一或 `generic_request`）, version_no int, definition_json jsonb, enabled bool, 四件套+row_version。unique(name, version_no)；**每 name 恰一个 enabled**（部分唯一索引）。
- `definition_json` 冻结结构：

```json
{ "nodes": [
    {"id":"n1","type":"approval","label":"负责人审批","approver":{"kind":"role","role":"project_manager"},"countersign":"any"},
    {"id":"n2","type":"condition","label":"金额≥5万","expr":{"field":"amount_cents","op":">=","value":5000000}},
    {"id":"n3","type":"approval","label":"管理层","approver":{"kind":"role","role":"partner"},"countersign":"all"}
  ],
  "edges": [ {"from":"start","to":"n1"}, {"from":"n1","to":"n2"}, {"from":"n2","to":"n3","when":true}, {"from":"n2","to":"end","when":false} ] }
```

- 节点类型冻结：`start/end/approval/condition`（本期四种）。approver.kind：`role/user/initiator_manager/project_manager`；condition.expr.field 限定白名单（`amount_cents/confidentiality/level/borrow/request_type`）。
- **编译与执行**：业务对象提交时，引擎按 biz_binding 取 enabled 流程定义 → 解析条件（表单快照求值）→ 展开为 approval_steps（实例化，含条件求值结果）；`policy_snapshot` 存流程版本号+解析后步骤。既有 `approval_policies` 种子**迁移为同名 flow_definitions**（默认流程），策略表保留只读兼容，不再新增。
- 既有 biz_type 全部可自定义流程（travel/travel_change/funding/expense/expense_adjustment/budget/change_request/access_grant/timesheet）；无自定义流程时用默认流程。
- 设计器校验（保存时服务端强制）：环检测、悬空节点、start/end 唯一、条件分支双边齐备、自审风险提示（解析为空时阻断发布）。

### 3.2 通用申请单（「大审批流」承载对象）

- `generic_requests`：id, code（新前缀 `REQ`）, request_type text（可配置类型种子：leave 请假/procurement 采购/seal 用章/other 其他，system_config 可扩充）, title, reason text, start_on/end_on date null, amount_cents null, attachment 引用, applicant_id, status `generic_request_status`(draft/pending_approval/approved/rejected/withdrawn), approval_instance_id, 四件套+row_version。
- 固定核心字段（title/reason/起止/金额/附件）——**不做自由表单设计器**。
- 走引擎（biz_type='generic_request'），全局 scope 流程。

### 3.3 API

`flow.list/getById/createDraft/updateDraft/publish {id, idempotencyKey}/disable/versions`（sysadmin/partner）；`genericRequest.list {mine|type|status}/getById/create/update(draft)/submit/withdraw`；审批中心 `approval.listMine` 增加流程节点进度（当前节点在定义图上的位置）。

## 4. B 域 · 基础数据与系统配置中心（/admin）

### 4.1 页面结构（sysadmin 专属，`admin.config` 动作门）

`/admin` 页签式：用户与组织｜客户与事项｜项目模板｜审批流｜系统参数｜编号规则（只读）。

### 4.2 API（admin.* 域，全部服务端鉴权+审计）

- `admin.userList/createUser/disableUser/enableUser/assignRole/unassignRole`（停用即时失效已有；创建用户口令=初始随机+首次登录强制改密）；
- `admin.clientList/createClient/updateClient`（停用而非删除）、`admin.matterList/createMatter/updateMatter`；
- `admin.templateList/updateTemplate`（structure_json 编辑+校验）；
- `admin.getConfig/setConfig {key, value}`（白名单键，前后值审计）；
- 自助（所有角色）：`auth.changePassword {oldPassword, newPassword}`（校验旧口令+全会话失效）+ `/settings` 页。

### 4.3 权限裁定

sysadmin 管配置但**不因此获得业务内容权**（arch/03 §4.5 不变）；客户/事项含密级，admin 界面显示元数据不含业务内容；partner 可读流程定义与配置（只读）。
