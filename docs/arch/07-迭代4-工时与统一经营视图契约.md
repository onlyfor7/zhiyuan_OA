## 2. 数据模型细案（2 张新表 + 1 处存量放宽）

- `timesheet_periods`：code(TS), user_id FK, period_type text default 'weekly', period_start/end date, status `timesheet_status`(draft/pending_approval/approved/returned/locked), approver_id FK null（提交时按 §4.2 解析）, submitted_at null, approved_at null, returned_note null, locked_at/by null, lock_reason null, 四件套+row_version。**unique(user_id, period_start)**。
- `time_entries`：period_id FK, user_id FK, project_id FK null（非项目内部工作可空，但 activity_type 必须是 internal_admin/other）, task_id/meeting_id/travel_id FK null, activity_type `time_activity_type`（arch/02 §3.1 六值落 pgEnum）, work_date date, duration_minutes int（**>0 且为整数分钟，禁止浮点小时**）, description text, billable bool default true（仅统计标记，不生成账单）, source `time_entry_source`(manual/prefill_meeting/prefill_travel/copy), 四件套+row_version。索引：(user_id, work_date)、(project_id, work_date)、period_id。
- **存量放宽（迭代 3 裁定落地）**：archive_links 二态 check 中 fv 空允许的 source_type 增 `funding`、`expense`（结构化经费/报销记录可归集到目录 11/10）。

## 3. 状态机（冻结）

| 对象 | 迁移 | 硬限制 |
|---|---|---|
| 工时周期 | draft → pending_approval → approved / returned → draft（修改后可重提）→ approved → locked | 批准后明细不可直接改；locked 普通修改禁止，unlock 需 `time.unlock` 授权+理由+审计 |
| 工时明细 | 随周期状态；draft 期可增删改 | approved/locked 期间明细只读；退回后恢复可编辑 |

**统计口径（§10.3 不变）：** 有效工时 = approved + locked；草稿/待审批/已退回**单列**，不得混入；预填与复制草稿不计入；驾驶舱与周报默认已批准工时，另列待审批（TIM-009）。

## 4. 关键规则

1. **填报校验（TIM-001/005，服务端强制）**：`duration_minutes` 整数 >0；同一用户同一 `work_date` 全部明细（跨周期）合计 >1440 分钟（24h）→ **阻止**（`VALIDATION_FAILED`）；时间重叠、单日 >540 分钟（9h）→ 警告（提交时 checks 展示，不阻断）；缺说明 → 警告（类别规则可配置为阻断）。
2. **审批人与职责分离（TIM-006）**：提交时解析 approver——申请人若含 `project_manager` 全局角色 → 指定 `partner`（项目负责人工时上级审批，**不得自审**）；否则 → 该周期内分钟数最多项目的 manager（无项目明细 → org 指定默认审批人种子）。走审批引擎 `biz_type='timesheet'`；退回必填意见（returned_note）→ draft 可改重提。
3. **锁定（TIM-007）**：approved 周期可由持 `time.lock` 动作角色（pm 对项目成员、partner 对负责人，财务可配置）锁定；unlock 需 `time.unlock` 专门授权 + 理由 + 审计，影响全部相关明细。
4. **预填（MTG-010/TRV-007）**：`time.prefillFromMeeting {meetingId, periodId?}` / `time.prefillFromTravel {travelId, periodId?}`——按迭代 2 的建议算法在**目标 draft 周期**（缺省取当前周期，没有则自动建）生成 `source=prefill_*` 的草稿明细；**可编辑、默认未提交、不计有效工时**；cancelled 会议/出差拒绝；重复预填按（meeting/travel + user + date）幂等去重。会议时长与出差天数只是草稿依据，未确认不得计入（§4.3 工时链）。
5. **复制草稿（TIM-004）**：`time.copyDay {fromDate, toDate}`——复制当日明细为草稿（source='copy'），提交前必须确认。
6. **统计（TIM-008/009）**：全部统计接口返回 `{ items, asOf, statusScope }`；`stats.byUser/byProject/byTask/byActivity {from,to,statuses[]}`；项目工时页按人员/任务/活动类型/日期分组可下钻；**同名指标各页面一致**（驾驶舱、周报、工时中心、项目空间读同一聚合函数）。

## 5. 全局搜索（CORE-004，本迭代落地）

`search.query { q, types?[], cursor, limit }`：

- 覆盖：project、task、meeting、travel、funding、expense、decision、quality_issue、weekly_report、time_entry（仅本人）、document（file_objects 名称）。
- **SQL 级权限过滤先于结果组装**（复用各域 scope filter）；无权限对象整体不可见——**不返回标题、编号前缀之外的任何信息，命中计数按可见集合**；金额字段仅在用户对该对象有财务可见权时返回（E2E-11）。
- 结果：`{ type, id, code, title, snippet?, projectId?, deepLink }`；深链直达对象页。
- 审计：搜索行为不逐条审计（普通查询），导出才审计。

## 6. API 契约清单（形态沿用 arch/02）

| 域 | 过程 |
|---|---|
| time | `myPeriod {periodStart}`（含明细与状态）、`saveEntries {periodId, entries[], idempotencyKey}`（draft 期覆盖式保存草稿）、`submit {periodId, idempotencyKey}`（解析 approver→引擎）、`withdraw`、`prefillFromMeeting/prefillFromTravel`、`copyDay`、`validate {periodId}`（§4.1 校验结果：阻止项+警告项） |
| time.approve | （走 approval.act）退回即 reject（意见必填）→ returned |
| time.lock | `lock {periodId, reason?}`、`unlock {periodId, reason}`（`time.unlock` 授权+理由+审计） |
| time.stats | `byUser/byProject/byTask/byActivity {from, to, statuses?, cursor}`、`mySummary {from, to}`（本人各状态分钟数+缺口）、`exportCsv {filters}`（审计） |
| search | `query { q, types?, cursor, limit }` |
| dashboard | summary 增：本周已批准工时/待审批工时（按角色范围）、预算执行沿用 |
| report | generateDraft 增 time 节（本周已批准工时按人员/活动类型汇总 + 待审批单列），来源可下钻 |

权限（arch/03 §3 矩阵执行）：本人明细本人可见可改（draft）；他人工时明细 pm（项目内）/partner（范围）可见；finance 仅必要统计；viewer 默认不见；锁定/解锁按 §4.3。

## 7. 集成点

- 工时中心 `/operations/time`（我的填报周日历+列表、审批队列、周期锁定、统计页）；项目空间「工时」页签真实数据。
- 工作台 todo 增：待提交工时（draft 周期有明细未提交）、待我审工时；驾驶舱时间卡。
- 周报 generateDraft 增 time 节；归档不变（工时是结构化数据，§12.1）。
- 通知：`timesheet_gap`（锁定期临近仍有 draft/returned 明细 → 填报人；审批积压 → 审批人）。
- 会议/出差详情「预填工时」按钮接通 time.prefillFrom*（替换迭代 2 的只读建议面板，建议面板保留为预览）。
