## 2. 数据模型细案（7 张新表 + 4 处存量修订）

通用字段沿用 arch/01 §2；编号前缀 `MTG`/`TRV` 已注册。

### 2.1 新表

- `meetings`：project_id FK, code(MTG), type `meeting_type`（arch/02 §3.1 冻结 5 值）, subject, agenda text null, start_at/end_at timestamptz, location text null, online_url null, organizer_id FK, recorder_id FK null, confidentiality_level, status `meeting_status`(planned/completed/cancelled), minutes_status `minutes_status`(none_required/pending_draft/pending_confirm/confirmed), cancel_reason null, actual_start_at/actual_end_at null, 四件套+row_version。**校验：end_at > start_at（DB check + API）**。
- `meeting_participants`：meeting_id FK, user_id FK null, external_name text null, external_org text null, role `participant_role`(required/optional), attendance `attendance_status`(planned/attended/absent/excused) default planned, notify_contact text null。**二态：user_id 与 external_name 恰一非空（check）**；unique(meeting_id, user_id) 部分索引。外部参与人只存必要信息，不建账号、不赋权。
- `meeting_minutes`：meeting_id FK, version_no int, body text, disagreements text null, risks text null, recorder_id, confirmer_id null, confirmed_at null, file_version_id FK null（确认版导出/附件）, created 两件套。unique(meeting_id, version_no)。**确认后本行只读；修改产新版本。**
- `meeting_action_items`：meeting_id FK, minutes_version_id FK null（来源纪要版本）, title, owner_id FK, due_date date, deliverable text null, checkpoint text null, status `action_item_status`(open/converted) , converted_task_id FK null, 四件套+row_version。
- `travel_requests`：project_id FK, code(TRV), applicant_id FK, reason text, destination text, start_on/end_on date, estimated_cost_cents bigint null（**仅提示，绝不写台账**）, borrow bool default false, borrow_amount_cents bigint null, status `travel_status`(draft/pending_approval/approved/rejected/in_progress/completed/closed/cancelled), approval_instance_id FK null, completion_summary null, actual_cost_note null, completed_at null, 四件套+row_version。
- `travel_segments`：travel_request_id FK, seq int, type `segment_type`(transport/accommodation/client_site/other), start_at/end_at timestamptz, from_place null, to_place null, description null, linked_meeting_id FK null, linked_task_id FK null。**同单内按 seq 顺序 start_at 不得倒挂（API 校验）**。
- `travel_events`（只追加）：travel_request_id FK, actor_id, action `travel_event_action`(create/submit/approve/reject/withdraw/change_submit/change_approved/depart/complete/close/cancel), payload_json null（变更前后值）, created_at。无痕修改禁止——关键字段变更历史以此为准。

## 3. 状态机（冻结）

| 对象 | 迁移 | 硬限制 |
|---|---|---|
| 会议 | planned → completed；planned → cancelled | 与纪要状态分离；取消必须 cancel_reason；cancelled 无工时建议、不产归档 |
| 会议纪要 | none_required → pending_draft → pending_confirm → confirmed | confirmed 后修改=新版本；未确认内容界面明确标识 |
| 出差 | draft → pending_approval → approved/rejected → in_progress → completed → closed；pending → draft（撤回）；approved → cancelled | 关键变更（日期/目的地/预计费用）必须走 travel_change 审批；完成 ≠ 费用已批准 |
| 行动项 | open → converted | converted 不可逆；任务状态以 tasks 为准（不复制完成态） |

## 4. 关键事务规则

1. **纪要确认**（meeting.minutesConfirm）：同事务——minutes 行确认（confirmed_at）+ meeting.minutes_status='confirmed' + 自动 archive.link（目录 09，fv 或 source 对）+ 确认人/记录人通知 + 审计。
2. **行动项转任务**（meeting.actionItemConvert）：同事务——task 创建（source_type='meeting', source_id=action_item_id, 继承 project/due_date/owner）+ action_item.status='converted' + converted_task_id 回填 + 审计。双向定位：任务详情可回链会议；行动项列表显示任务状态（join，不复制）。
3. **分歧转决策**（meeting.escalateToDecision）：decision.create 带 source_type='meeting', source_id=meeting_id + minutes_version_id 上下文；会议详情可查关联决策。
4. **出差审批通过**（引擎 handler）：同事务——travel.status='approved' + travel_events + 通知申请人；**不写任何预算占用**（TRV-004）。借款/超阈值/会签由审批策略匹配驱动（§7）。
5. **出差完成**（travel.complete）：同事务——状态 + 实际行程/结果摘要 + travel_events + 归档（目录 10：申请材料链接）+ 「返回报销」提醒通知（差旅费模块迭代 3 承接）。**完成不产生任何费用记录**。
6. **变更重审**：travel.submitChange（approved/in_progress 态）→ 冻结当前快照 → 引擎（biz_type='travel_change'）→ 通过后在同事务应用关键字段 + events 记录前后值；驳回原状不动。

## 5. API 契约清单（形态沿用 arch/02）

| 域 | 过程 |
|---|---|
| meeting | `list {projectId?\|mine\|dateFrom/dateTo\|status, cursor}`、`getById`（含参与人/材料/纪要版本/行动项/关联决策）、`create`、`update`（planned 态+row_version）、`transition {id, action: complete\|cancel, ...}`（cancel 必填 reason）、`recordAttendance {id, entries[]}` |
| meeting.minutes | `saveDraft {meetingId, body, disagreements?, risks?, row_version?}`（pending_draft 编辑或 confirmed 后产新版本）、`submitConfirm {meetingId, versionNo}`（→pending_confirm，指定 confirmer）、`confirm {meetingId, versionNo, idempotencyKey}`（确认人身份校验）、`versions {meetingId}` |
| meeting.action | `addItem {meetingId, minutesVersionId?, title, ownerId, dueDate, deliverable?, checkpoint?}`、`convertToTask {id, idempotencyKey}`、`list {meetingId}`（join 任务状态） |
| meeting.extra | `escalateToDecision {meetingId, minutesVersionId, title, context}`；`timePrefillSuggestion {meetingId}` → `{minutes, projectId, attendeeUserIds}`（**只算不存**；cancelled/none_required 返回 null） |
| travel | `list {projectId?\|mine\|status, cursor}`、`getById`（含分段/事件流/审批实例/关联文件）、`create`（含 segments 一次提交）、`update`（draft+row_version）、`submit {id, row_version, idempotencyKey}`、`withdraw`、`transition {id, action: depart\|complete\|close\|cancel, ...}`、`submitChange {id, changes:{...}, reason, idempotencyKey}` |
| travel.extra | `timePrefillSuggestion {travelId}` → 按分段日期给每日建议分钟数（**只算不存**，不按 24h）；`segmentsValidate` 并入 create/update 服务端校验 |
| approval | 复用引擎；新增 biz_type：`travel`、`travel_change`；act 消费 acted_idempotency_key（N4） |
| archive | 复用；tree/directoryItems 支持 fv 与结构化来源（meeting/travel/report）混合列出 |
| todo | mine 增两源：**待我整理纪要**（记录人，会议已结束且纪要 pending_draft）、**待我确认纪要**（确认人，pending_confirm） |
| dashboard | summary 增：本周会议数、出差中人数（权限过滤） |

权限：会议按项目成员/参会人可见（参会人≠成员时仅可见该会议，不进项目权限）；出差按申请人/项目负责人/审批人/财务（必要信息）可见；外部参与人无任何平台访问。密级沿用 arch/03。
