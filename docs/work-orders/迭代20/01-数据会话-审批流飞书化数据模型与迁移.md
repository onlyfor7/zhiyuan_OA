## §1 custom_form_defs 建表（arch/14 §4.1）

新表 `custom_form_defs`（schema 文件建议 `server/src/db/schema/approval-ext.ts` 或并入现有 extensions.ts，随现有组织习惯）：

| 列 | 类型/约束 |
|---|---|
| id | uuid PK default gen_random_uuid() |
| code | text 唯一（CF-YYYY-NNNNN，走 next_code 序列，§5） |
| name / description / icon | text / text / text（icon=图标 key，允许 NULL） |
| group_name | text NOT NULL default '通用' |
| visibility | jsonb NOT NULL `{mode:"all"\|"roles"\|"users", roleKeys?: string[], userIds?: string[]}` |
| form_schema | jsonb NOT NULL `{fields: FieldDef[]}`（FieldDef 见 shared 类型，§4） |
| form_version | integer NOT NULL default 1 |
| flow_id | uuid NULL FK → flow_definitions.id ON DELETE RESTRICT（1:1，加唯一索引） |
| status | pgEnum `custom_form_status`：draft/published/disabled，NOT NULL default 'draft' |
| 审计四件套 + row_version | 同现有表惯例 |

索引：code 唯一、flow_id 唯一、status 普通、group_name 普通。

## §6 v1→v2 迁移（核心）

1. **纯函数** `migrateFlowV1toV2(def)`（放 `server/src/db/migrate/flow-v2.ts` 或同级工具文件，可单测导入）：
   - v1 线性链（start→…→end）→ v2 nodes 有序数组；approval 节点字段平移（label→name，approver/countersign 不变，ops/settings 填默认）。
   - v1 condition（when true/false 双边）→ v2 condition 节点两分支（true 分支 expr 原样，false 分支=else 放最后）。
   - 无法机械迁移的形态（理论上不应存在；如实检测）→ 抛错列入回执 anomalies，不硬转。
2. **迁移脚本**（npm 脚本 `db:migrate:flow-v2`，幂等）：
   - 先建备份表 `flow_definitions_bak_20`（`create table … as select *`；已存在则跳过）；
   - 逐行 `definition_version=1` 的流程：转换 → 同事务更新 definitionJson + definition_version=2；
   - 回执输出：processed/converted/anomalies/backupRows，逐流程 name+versionNo 一行；
   - 二次运行为零变更（幂等）。
3. **种子同步**：`server/src/db/seed` 中默认流程定义改写为 v2 结构（种子幂等 upsert 语义保持）；种子即 v2，新库不再产生 v1 行。
4. **项目模板内嵌流程**（若有定义内嵌于模板 jsonb）：一并检测迁移；若模板只存 bizBinding 引用则无需动，回执注明。

## §7 测试（server/tests/db/ 追加）

1. 干净 lexflow_test 库重放：新表/新列就位、迁移 0016 起幂等（重复 migrate 零漂移）。
2. `migrateFlowV1toV2` 单测：线性链、含条件双边、含抄送外全部 v1 形态 → v2 结构断言；异常形态进 anomalies。
3. 迁移脚本对种子库执行：回执 processed=种子流程数、anomalies=0、二次运行零变更、备份表行数=流程数。

5. 种子二次执行行数不变（既有幂等门禁保持绿）。
