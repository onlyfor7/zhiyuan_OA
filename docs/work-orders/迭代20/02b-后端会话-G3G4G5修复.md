## §1 G3：自定义表单 schema 非管理角色可读（arch/14 §4.3 意图）

- `forms.getById`：非管理角色放行只读——限 **published** 表单且调用者命中 visibility（all/roles/users 逐层判定，复用提交校验的同一函数，禁止两套口径）；draft/disabled 或非命中 → 同形 404。
- `forms.listPublic`：对 visibility 命中者携带 `formSchema`（及 formVersion）——发起入口渲染所需，无需二次调用。
- 审批详情/申请单详情输出：自定义表单快照区附 `formSchema`（快照 form_version 对应版本结构）+ field label 映射所需数据，供前端 key→label 渲染（当前快照区只出原始 key）。
- 用例：member 命中 roles 可读 schema / 非命中 404 / draft 表单 404 / listPublic 携 schema 字段。

## §2 G4：return prev 再到达重挂（arch/14 §7「指针回拨」语义）

- 现状缺陷：退回步标 skipped+[returned] 后被永久旁路——上一步再批准，实例直接终审（实测 APR-2026-00284）。
- 修复：引擎前进经过 `[returned]` 步时**重置为 pending**（actedBy/comment/actedAt 清空、留「重挂」痕迹），使其重新待审；dedupe once 不得把重挂步自动跳过（退回重审属新审批行为，去重仅对同次前进序列生效）。
- 边界：return initiator（回草稿重交）不受影响；连续退回语义保持一致。
- 用例：退回 prev→上一步再批准→returned 步重新 pending→该步再批准→实例 approved（终审在重审之后，不得提前）；再拒绝路径 instance rejected。

## §3 G5：末端抄送终审触发（arch/14 §8「结束时抄送」）

- 现状缺陷：末端 cc（afterStepIndex=总步数）在末步**到达**时即发出，终审补发被 ccFired 守卫挡住；若末步随后被拒绝，抄送已误发。
- 修复：末端 cc 仅在实例进入 **approved 终态**后触发；中段 cc 维持「到步即触发」（线性流程中与「上步通过后」等价，语义不变）。
- 用例：末端 cc 在末步 pending 时不发 → 批准后到达（通知+审计 approval.cc）→ 拒绝路径全程无 cc。
