## §1 编译器 v2（`services/approval/flow.ts` 扩展，或新文件 `flow-v2.ts` 由你定）

1. `validateFlowStructureV2(raw)`（保存时 FLOW_INVALID 400，字段级落位）：
   - `schemaVersion===2`、`nodes` 为有序数组；节点类型 ∈ FLOW_NODE_TYPE_V2；
   - approval 节点：approver.kind ∈ v1 五种 ∪ v2 四新；参数齐（role→role、user→userId、manager_chain→levels∈[1,10]、form_contact→fieldKey 非空）；approvalType ∈ manual/auto_pass/auto_reject；sameAsInitiator ∈ SAME_AS_INITIATOR；ops 形态合法；
   - condition 节点：branches ≥2、else（expr 缺省）必须最后、分支 name 非空、expr 字段校验复用现有规则（固定业务表单走 FLOW_CONDITION_FIELDS 白名单；自定义表单流程允许 `form.<fieldKey>`）；嵌套深度 ≤3（FLOW_V2_LIMITS）、总节点数 ≤100；
   - cc 节点：receivers 非空且 kind 合法。
2. `compileFlowV2(def, formSnapshot, exploreBoth, resolveConfig)`：
   - 顺序遍历 nodes；condition 按快照逐分支求值、**第一命中分支**进入（else 兜底），递归编译其子序列后汇合主干；
   - cc 节点 → 产出 `ccEvents`（不产审批步骤）；
   - approval → 步骤（含 approvalType/ops/sameAsInitiator/fieldPerms 透传入步骤结构）；
   - exploreBoth=true（发布校验）时全分支展开。
   - $config 编译期求值沿用现有 resolveConfigValue。
3. `compileFlow` 改双读分发：按 `definition_version`/`schemaVersion` 分派 v1（现逻辑只读保留）/v2；`findEnabledFlow` 不变。

## §2 引擎运行时扩展（`services/approval/engine.ts`）

1. **新审批人策略解析**（resolveKind 扩展）：
   - `initiator_self` = 实例 applicantId；
   - `dept_head` = 提交人所在部门的负责人（org_units.leader 字段，查 org 结构；无负责人 → 发布/提交时 412/400 如实报错）；
   - `manager_chain` = 沿提交人 manager_id 树向上 levels 级，**逐级各成一步**（候选人不足提前终止）；
   - `form_contact` = 从实例 payload（form_snapshot 内 form.<fieldKey>）取人员 id；仅 `custom_form:*` bizBinding 可用；
   - `initiator_choice` 增强：选择范围 all/roles/users（steps 结构带 scope 限定，提交时校验自选人在范围内）。
2. **sameAsInitiator** 四态：解析候选人后若含提交人本人——self 照审 / skip 该步标 skipped / to_manager 替换为直属上级 / to_dept_head 替换为部门负责人。
3. **去重**（settings.dedupeApprover=once）：同一审批人在本实例前面步骤已 approved → 本步自动 skipped（留痕注明 dedupe）。
4. **auto_pass / auto_reject**：到步即由系统自动落（actedBy=NULL、comment 标记 `auto`、审计事件）；auto_reject 进入 rejected 链。
5. **退回**（act 新 action `return`，节点 ops.returnBack≠none 时可用）：
   - `prev`：当前步标 returned（用现有 skipped 或新增语义均可，须可区分展示），currentStepSeq 回拨上一审批步并重置其 pending；
   - `initiator`：实例退回提交人——状态回退为可修改草稿语义（业务方 onReturned 钩子：业务单回 draft），提交人修改后重新提交从头走；
   - 全程留痕（步骤行 + 审计）。
6. **requireCommentOnReject/Approve**：act 时按节点 ops 强制。
7. **抄送**：编译产出的 ccEvents 在对应时机（到步/提交/完成）经 `notify` + `emitEvent` 发出；抄送人获得实例只读可见（不含操作按钮）；cc 事件入审计。
8. **表单权限矩阵 fieldPerms**：实例详情/审批卡快照输出按「当前查看者所处节点」的 fieldPerms 过滤——hidden 字段不进序列化；read 只读；**edit 本期不落运行时**（设计器可存，运行时忽略并在 API 注释注明 P2）。

## §3 自定义表单服务端（新模块 `modules/forms/`）

- CRUD：`forms.create`（草稿：CF 编号+同事务建绑定 flow_definitions 草稿，`bizBinding=custom_form:<code>`、scope=global、definition_version=2）/ `forms.updateDraft`（form_schema 校验：控件∈FORM_CONTROL_TYPE、key 唯一合法、options 非空（选项类）、数值范围 min≤max、人员/文件控件单值）/ `forms.publish`（绑定流程发布校验联动 assertFlowPublishable + 状态机 draft→published；published 后表单结构冻结，改动须产新 form_version）/ `forms.disable` / `forms.delete`（仅 draft）/ `forms.list`（按 group_name 分组）/ `forms.getById`。
- 管理权限：sysadmin+partner（与流程管理同门槛）；`forms.listPublic` 按 visibility 过滤（发起入口用）。
- **提交链**：generic_request 扩展——request_type=CF code 时：① 表单须 published；② 提交人过 visibility；③ payload 按 form_schema（提交时 form_version 快照）逐字段校验（必填/类型/选项域/数值范围/person 用户存在/person 启用态/file 引用存在），非法 400 fieldErrors 逐字段落位；④ form_snapshot 合并 `form.<key>` 供条件求值；⑤ 引擎 bizType=`generic_request` 沿用，findEnabledFlow 用 `custom_form:<code>`。
- 详情渲染输出：form_schema（快照版本）+ payload 一并返回（前端按 schema 渲染）。
