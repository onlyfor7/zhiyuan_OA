# 迭代 5 · 工单 06：「佳力奇咨询项目」全周期模拟试用（测试会话）

**依赖：** 迭代 5 已交付（补充试用单，应用户要求代替真人试用）　**产出分支建议：** `iter5/trial-jlq`
**目标：** 以拍级精度模拟一个虚构项目「佳力奇咨询项目」的全生命周期，产出**时序性、逐步骤、带系统截图**的详细测试流程报告，供用户亲自审阅并反馈意见。

## 执行环境

- **栈：prod（http://localhost:8080）**——以交付形态试用；Playwright/CDP **真实点击**，禁止直接调 API 代替 UI 操作（API 仅可用于 DB 断言复核）。
- 截图：每一步保存到 `D:\tmp\shots-jlq\`，文件名 `P<阶段>-<步骤号>-<动作>.png`（如 `P3-04-提交纪要.png`）。
- 角色阵容（既有种子账号，口令 Demo@2026）：partner 周正（立项/重大审批）、pm 陈立（项目负责人）、member 林晓（执行）、finance 财务、archivist 档案、quality 黄磊（huanglei@）、sysadmin、viewer。

## 环境准备（架构特批）

种子增补虚构客户「佳力奇科技（虚构）」+ 事项「佳力奇咨询」后重跑 `npm run db:seed`（幂等，不重建库）。**理由：主数据（客户/事项）创建无 UI——本期未排期，属已知覆盖缺口，必须在报告「未覆盖清单」如实列明。** 除此外一切操作必须走 UI。

## 时序剧本（P1–P12，逐步执行；每步=角色/页面/点击按钮/预期结果/截图）

| 阶段 | 内容（必须全部走完） |
|---|---|
| P1 立项 | partner：/projects/new 全字段表单（模板=常年法律顾问、客户=佳力奇、负责人=陈立、成员、密级）→ 创建成功直进项目空间；pm：总览/成员页签核对自动生成物 |
| P2 计划与任务 | pm：计划页签三轨甘特、任务创建/流转/改派、里程碑到达、模拟调整面板（不落库） |
| P3 会议链 | pm 创建立项会（内外部参与人）→ 完成 → member 整理纪要 → 提交确认 → pm 确认固定 → 行动项一键转任务（双向定位）→ 分歧转决策（带入上下文）→ 档案 09 归集可见 |
| P4 出差链 | member 出差申请（分段+借款）→ pm+finance 会签 → depart → complete（摘要+归档 10+报销提醒） |
| P5 预算与经费 | partner 建预算（类别行）→ member 经费申请（关联出差）→ 审批 → 占用台账可见、四数一致 |

| P7 工时 | member 填报+会议/出差预填（草稿标识）+复制当日 → 提交 → pm 审批 → partner 锁定 → member 尝试编辑被拒 → partner 解锁（理由+审计） |
| P8 质量与决策 | quality/pm：问题登记→处理→复核分离（自审负例）→阻断演示；决策单四必填+检查点成任务+执行验证 |
| P9 周报与档案授权 | pm 周报生成→确认→归档（版本链）；archivist 审批授权；viewer 凭授权只读访问、撤销后即时 404 |
| P10 结项检查与审计 | pm 结项检查单（未决事项列出）；sysadmin /audit 真实审计表；全局搜索三角色（member/finance/viewer）结果差异对比 |

## 输出（报告硬性格式）

`docs/测试报告/佳力奇全周期模拟试用报告.md`：**时序排列**，每步一行条目：`[P3-04] 14:02 | 角色:member 林晓 | 页面:/meetings/:id | 操作:点击「提交确认」| 预期:进入待确认 | 实际:一致 | 截图:P3-04-提交纪要.png`。覆盖矩阵：本仓 41 条路由 × 每页主要按钮逐一核对，**未覆盖项单列清单+理由**。发现的缺陷/卡点按「页面/角色/操作/期望 vs 实际」四要素记录。

## 纪律与边界

1. 「收回款」（客户计费/收款）属基线 §2.3 范围外——以最接近的在-scope 能力（费用支付登记+预算执行口径）演示并在报告注明「回款不在本期范围」。
2. 所有金额/工时须与台账抽查一致（报告附 3 处勾稽复核截图或 DB 断言）。
3. 失败如实记录并区分「脚本适配/应用缺陷」；不得跳过失败步骤。
4. 口令/密钥不出现在报告；截图注意无真实敏感信息（全虚构）。
