## 1. 角色与导航呈现

- 六角色（sales/sales_manager/presales/operations/regional_vp/ceo）使用既有 `GLOBAL_ROLE_LABEL`，组织员工页徽标正常显示。
- CRM 菜单按新范围呈现：销售/主管/售前/运营/大区 VP/CEO/partner/sysadmin 可见；member、viewer 等仍不渲染客户组明细入口。
- 员工维护表单增加**直属主管**选择（读 `managerId`，写 `org.members.update`），展示主管链；成环/无权限错误按 fieldErrors 落位，不弹 Toast 冒充成功。
- 小元、通知、报表等既有页面不因为新角色出现空白错误；无权限仍按提示页三类区分规则。

## 2. CRM 页面改造

### 线索

- 线索列表、详情抽屉、导出/复制文本中**不再展示线索编号**；18-01 的 `lead.code ?? ""` 临时兜底由本棒正式移除或改为无编号呈现。
- 新建线索不展示编号字段；历史数据即使有 LD 值，也不在新 UI 展示。
- 转化入口改为两条清晰路径：
  - **新建商机**：客户（选择/新建）、商机名称、预计金额、赢率、项目负责人（必填）、售前（可选）；
  - **关联既有商机**：目标商机选择器只列当前用户可管理范围；提交 `opportunityId`，成功后跳商机详情/抽屉。

### 商机

- 新建商机表单补：项目负责人（必填 UserPicker）、售前（可选）、`idempotencyKey`。幂等键在打开表单时生成一次，校验失败重试沿用；表单成功关闭后废弃。
- 商机详情/抽屉显示：OPP 编号、来源线索（如有）、负责人、售前、项目负责人、关联项目（code/name）、阶段、金额、赢率、关闭原因/时间；won/lost 终态只读沿用。
- 商机操作：阶段推进、售前指派、关闭（原因必填）、赢单挂合同；合同激活入口只在 draft 时出现。
- 商机详情与项目详情互跳：`projectId/projectCode` 直跳项目空间；项目概览显示 `opportunity` 最小标识并可回跳商机。

### 可见性反馈

- 销售只看本人，主管看下级，售前看指派，运营/管理层看全局；空态文案分别说明“当前范围内暂无线索/商机”，不得误导为系统异常。
- finance 合同前只能见汇总，不明示被隐藏的记录名称；合同激活后可进该合同链明细。
- 所有列表计数与内容必须一致；不得只隐藏行而保留汇总计数。

## 3. 项目全周期呈现

- 项目列表/空间明确标识“售前/交付/已关闭”：
  - 商机项目在售前阶段显示“售前”徽标；
  - 合同激活后同一项目切到交付视图，不出现第二个项目卡片；
  - 商机关闭后项目显示已关闭并只读。
- 项目空间从售前阶段即可管理任务、会议、出差、费用与文件；前端不得因 type=`售前` 或 type 徽标未知而布局破裂。
- 存量商机项目缺计划时，负责人/运营/sysadmin 在项目或商机详情看到“补建售前计划”入口，调用 `crm.opportunities.ensureProjectPlan`；成功后刷新计划，重复点击不重复建版本。

## 4. 节点级甘特图

- 项目甘特改接 `plan.gantt`：只给阶段/里程碑画时间条，**任务不再生成时间条**。
- 节点行可展开任务摘要，仅显示完成/逾期/延后计数与任务清单链接（或抽屉列表），状态颜色遵循图标/语义规范。
- 基线、当前、模拟、实际轨沿用；售前节点也进入甘特。
- 移动端仍保持零横向溢出，甘特工具画布允许受控横滚（既有例外）。

## 5. 成本分段与管理员纠正入口

- 项目核算页/报表项目核算展示三个加性指标：售前成本、交付成本、总成本；总成本必须与既有直接成本一致，不得视觉上双算。
- 管理员配置中心新增“数据纠正”入口（建议独立页签）：对象类型 → 目标记录 → 白名单字段编辑 → 理由必填 → 提交 `admin.correctRecord`。
- 字段集按后端白名单最小集；员工主管字段接 manager picker；rowVersion 从详情/列表取。users 无 rowVersion 的既有裁定下，员工对象不展示版本号输入。
- 成功显示审计已记录提示；409/400 fieldErrors 落表单。禁止任意 SQL 输入框。

## 6. 表单与体验硬约束

- 创建/转化/关闭/赢单/激活/纠正均沿用现有弹窗规范、防重复提交、错误保留输入。
- 幂等键不得每次输入变化都重建；同一次表单重试必须同键。
- 375 视口：CRM 列表继续卡片化，转化分步弹窗全屏，互跳链接不遮挡小元宠物。
- H1/H2、图标注册表、表格列对齐、提示页三类区分不破。

## 8. 架构复核打回/接口依赖（2026-11-13）

当前实现不通过验收。先由后端完成 `18-02c`，前端再复修以下联动项；不得扩大范围。

### D-18-3-1 转化新建商机的售前选择未真正提交

- 代码证据：`LeadConvertDialog` 收集了 `presalesId`，但 `submitNew` 的 `opportunity` 请求体未携带；同时服务端 `crm.leads.convert` schema 也未接收该字段。
- 结果：页面看似“售前可选”，实际转化后 `presales_id` 恒为空，属于假功能。
- 处理：18-02c 后端先补 schema/service/测试；前端随后把 `presalesId` 加入转化请求，并在走查中证明落库。

### D-18-3-2 主管链读取缺口（原 G1）

- `org.members.list` 与 `admin.userList` 不返回 `managerId/managerName`，当前编辑弹窗无法预填和展示现主管。
- 处理：18-02c 补齐读取；前端随后预填直属主管，至少展示直属主管；若后端提供 `managerChain`，展示完整链。

### D-18-3-3 报表项目核算三列缺口（原 G2）

- rows 已有三成本字段，但报表列定义缺失，报表页无法展示。
- 处理：18-02c 后端补列定义；前端复核报表 Excel 页三列显示、数值右对齐。

### D-18-3-4 数据纠正客户/项目 rowVersion 未自动取得

- 当前客户/项目目标选择后 `rowVersion` 输入为空，需要管理员手工输入，违背本工单“rowVersion 从详情/列表取”。
- 前端修复：选择客户/项目后调用既有详情查询自动取当前 `rowVersion`；加载中禁止提交，失败不落假成功。用户对象继续按裁定不展示版本号。

### 复修后验收

除原有质量门与走查外，必须新增证据：转化新建商机 `presalesId` 落库且售前可见；主管预填/展示正确；报表三列可见；客户/项目纠正不手工输入 rowVersion 也可成功，409 冲突仍落表单。
