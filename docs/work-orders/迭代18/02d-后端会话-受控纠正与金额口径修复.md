## 1. O-18-5-1：`admin.correctRecord object:"user"` 返回 500

**根因（架构已核）：** `users` 表无 `row_version` 列，但 `correctRecord` 通用 UPDATE 对所有对象追加 `row_version = row_version + 1` 并以 `row_version` 过滤，导致 SQL 错误 500。

修复要求：

- user 对象走独立更新路径：
  - `before` 快照记录 `updated_at`；
  - SET 仅白名单字段 + `updated_at = now`，**不得引用 row_version**；
  - WHERE `id = input.id AND updated_at = before.updated_at`，实现既有裁定“服务端快照内部乐观校验”；
  - 影响行数 0 → 409 `STATE_CONFLICT`；
  - 审计 before/after 全快照、理由、patchedFields 保持。
- lead/opportunity/client/project 继续走 row_version 乐观锁，不得借机改弱。
- 主管校验保持：active、不可本人、多级不成环。
- 测试：
  1. user 纠正职位成功 200，DB 落值，审计 before/after/理由齐全；
  2. user 纠正 managerId 成环 400；
  3. user 非白名单字段 400；
  4. user 并发快照冲突路径 409（可用直接并发或受控构造）；
  5. 其余四对象既有纠正用例不回归。

## 2. O-18-5-3：客户详情 finance 合同金额与 D4 不一致

**根因（架构已核）：** `crm.customers.getById` 对合同子表只按 `scopeCanSeeAmounts(scope)` 剥离，缺少 `finance && contract.status === 'active'` 例外；同时 plan 行金额字段不能在外层金额不可见时泄露。

修复要求：

- 客户详情合同子表金额口径与 `crm.contracts.list/getById` 完全一致：
  - 全局/tree/presales 范围内按既有口径可见；
  - finance 仅 `active` 合同可见 `amountCents/cumulativeReceivedCents` 与付款计划金额；
  - finance 的 draft/terminated 合同不得显示外层或 plan 行金额；
  - 其他无权形态仍不得见金额。
- `crm.contracts.list/getById` 同步复查 plan 行金额剥离，不能只隐藏外层字段。
- 商机金额对 finance 继续隐藏（D4：财务不看无关商机明细）。
- 测试：
  1. finance 客户详情中 active 合同金额/累计回款/计划金额可见；
  2. 同一客户 draft 或 terminated 合同外层与 plan 金额全部缺席；
  3. partner/operations 口径不回归；
  4. member 仍同形 404 或空集；
  5. 既有 D-18-2-1~5、18-02c 测试不回归。
