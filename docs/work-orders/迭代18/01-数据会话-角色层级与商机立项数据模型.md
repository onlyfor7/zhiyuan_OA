# 迭代 18 · 工单 01：角色层级与商机立项数据模型（数据会话）

**依赖：** 工单 00；arch/13 v1.0 §1/§3/§5/§11。
**产出分支建议：** `iter18/data-foundation`
**边界：** 只改数据模型、shared 枚举/常量、种子与 server db 测试；不得改业务 modules/routes/前端，不得改既有已提交迁移，不得动外测 prod。

## 范围

### 1. 角色与主管关系

- `shared/enums/core.ts` 的 `ROLE_KEY` 增补六个 key：`sales`、`sales_manager`、`presales`、`operations`、`regional_vp`、`ceo`；名称与职责按 arch/13 §3.1 写入角色种子。
- `users` 增 `manager_id uuid NULL REFERENCES users(id) ON DELETE RESTRICT`，加普通索引；至少阻止 `manager_id = id` 的自引用。多级成环由后端在 18-02 校验。
- full 种子新增清晰的演示账号与主管树（销售 A/B、销售主管、售前、运营、大区 VP、CEO 各 1 个），不擅自调整现有 22 人的岗位；口令沿用当前演示约定。minimal 种子只补角色与必要枚举/配置。

### 2. 线索去编号

- `crm_leads.code` 改为可空；新数据不再生成 `LD-` 编号。历史值保留；数据库唯一约束需允许多个 NULL（PostgreSQL 默认语义）。
- 编号前缀注册表中 `LD` 保留为历史保留项并注明不再发放新号；不删除旧前缀造成历史数据失义。
- 数据测试断言可在同一表插入多行 `code = null`。

### 3. 商机立项与售前字段

`crm_opportunities` 增补：

| 列 | 规则 |
|---|---|
| `source_lead_id uuid NULL REFERENCES crm_leads(id) ON DELETE RESTRICT` | 直接建商机为 NULL；线索转化可关联来源 |
| `presales_id uuid NULL REFERENCES users(id) ON DELETE RESTRICT` | 售前指派基础，二期做完整协同 |
| `project_id uuid NULL REFERENCES projects(id) ON DELETE RESTRICT` | **加唯一索引**；新商机 18-02 起必须建立，存量由迁移补齐；一商机一项目、一项目最多一商机 |
| `closed_reason text NULL`、`closed_at timestamptz NULL` | 关闭商机必填原因与时间的落库基础；终态规则由后端 18-02 实施 |

- 不新增商机/项目双成本对象；不改 `expense_items/travel_requests/funding_requests` 的 `project_id` 结构。
- 项目生命周期枚举不新增售前状态：商机项目沿用 `preparing`，合同激活后转 `in_progress`，关闭后转 `closed`。

### 4. 售前项目模板

- full/minimal 种子按既有项目模板机制补充“售前项目模板”，节点覆盖：需求调研、方案与报价、商务签约；沿用既有 `structure_json` 格式和默认工期规则。
- 运行时自动立项由 18-02 后端事务消费模板；本工单仅允许为**种子演示商机**做数据级项目/计划补齐，不得新增业务 service 逻辑。

### 5. 存量商机项目补齐（迁移内完成）

- 对每条既有商机建立唯一项目关联：
  1. 能通过赢单合同/事项**唯一**确认既有项目的，补写 `crm_opportunities.project_id`，禁止新建；
  2. 无法唯一确认的，同事务创建客户业务事项（matter）与项目，再补关联；事项沿用既有客户链，项目编号走既有序列规则；
  3. 项目负责人取“可唯一确认的既有项目负责人”，否则取商机负责人；项目成员补 manager + 商机 owner；
  4. 开放商机项目为 `preparing`；won 且存在 active 合同的为 `in_progress`；lost 为 `closed`；
  5. lost 的 `closed_reason/closed_at` 优先从既有 `crm.opportunities.markLost` 审计快照回填；确实无历史快照时使用统一迁移文案与时间，并在回执中单独计数。
- **种子同步要求**：full 种子里既有/新增演示商机也必须具备关联事项、唯一项目、项目负责人/销售成员和首版售前计划；不能只依赖 18-02 后端事务。minimal 种子不造演示商机，但模板和约束仍须就位。
- 迁移必须输出回执：处理条数、复用项目数、新建项目数、异常数；异常不允许静默跳过。
- 迁移/种子重复执行不得产生重复事项、项目、成员、计划或编号；唯一约束兜底。
