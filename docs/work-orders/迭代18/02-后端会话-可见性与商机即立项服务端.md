# 迭代 18 · 工单 02：可见性与商机即立项服务端（后端会话）

**依赖：** 18-01/01b 架构验收通过；arch/13 v1.0 §3–§7/§10/§12。
**产出分支建议：** `iter18/server-foundation`（基线 `iter18/data-foundation`）
**边界：** 不改数据库 schema/迁移/种子，不改 app 前端，不改部署，不动外测 prod；如需新列或新枚举，先回架构仲裁。

## 1. CRM 可见性矩阵（服务端 SQL 级）

实现统一数据范围解析器（建议 `server/src/services/access/crm-scope.ts`），禁止在各路由内存过滤或只改菜单：

- `partner / operations / ceo / sysadmin`：全局 CRM 范围（sysadmin 按 D3 提升；operations 只读全局不代表项目写权）。
- `sales`：本人 `owner_id` 范围。
- `sales_manager / regional_vp`：本人 + `users.manager_id` 递归下级；递归结果进入 SQL `IN` 条件。
- `presales`：`presales_id = 本人` 的商机及关联线索/客户/跟进/项目售前内容。
- `finance`：CRM 明细仅在关联合同 `active` 后可见；合同前只能调用聚合端点。
- `project_manager/member/quality_lead/archivist/viewer`：不得再因全局角色获得 CRM 明细；只能获得本人项目交付所需最小信息或专用汇总。
- 线索、商机、客户、联系人、跟进、合同、付款计划的列表/详情/搜索/报表/导出均使用同一解析器；越权详情维持 `ACCESS_DENIED_OR_GONE` 同形 404。
- 商机金额不再只按 `fin.read` 剥离：记录范围内的销售、主管、售前、运营、管理层可见本人/管辖商机金额；合同前财务只见聚合金额，不见明细。
- 新增只读聚合端点 `crm.summary`（名称可微调，但契约须明确）：仅返回计数与金额汇总、不含名称/uuid 清单/联系人/跟进内容；供合同前财务与交付后端查看整体数据。

主管树维护：组织用户读写端点暴露并允许 sysadmin 维护 `manager_id`；变更前做多级成环校验（A→B 后禁止 B→A 或更长环），自引用由 DB check 兜底。部门归属与主管链不得混用。

## 2. 商机成立即立项事务（D5）

统一实现内部 helper（供直接创建与线索转化复用），全部在**同一事务**完成：

1. 商机写 `OPP` 编号、`sourceLeadId`、销售 `ownerId`、可选 `presalesId`、`idempotencyKey`。
2. 项目负责人为必填输入 `projectManagerId`，不得隐式默认给当前销售；校验用户 active。销售 owner 与项目负责人分别写入 `project_members`（同一人只保留 manager）。
3. 自动创建客户业务事项（matter）与项目（`PRJ` 编号、type=`售前`、lifecycle=`preparing`），回写 `crm_opportunities.project_id`。
4. 按“售前项目模板”实例化首版计划、阶段及模板任务/检查项；档案目录沿用项目创建既有规则。禁止复制一份半成品模板逻辑。
5. 编号、审计、项目、成员、计划与商机回写任一步失败整体回滚。
6. `idempotencyKey` 对直接创建必填：同键同载荷重放返回既有商机+项目；同键异载荷返回 409；并发撞唯一索引后重查返回，不得报 500。
7. 线索转化保留“已 converted 返回现状”幂等；转化新建商机时把 lead 写入 `sourceLeadId`，并同时维护既有 `converted_*` 回指。允许关联既有商机，关联时不得新建项目。

存量项目兜底：18-01 迁移项目可能没有售前计划。新增幂等 mutation（如 `crm.opportunities.ensureProjectPlan`）供负责人/operations/sysadmin 对关联项目补建售前模板计划；已有 v1 计划直接返回现状。普通 query 不得产生写副作用。

## 3. 商机终态与合同激活

- `markLost`：原因与时间写入 `closedReason/closedAt`；同事务将唯一关联项目置 `closed`，保留历史并审计。终态商机不可再改；其关联项目禁止新增费用、差旅、经费和任务（沿用统一错误形状）。
- `markWon`：继续要求合同；若合同 `activate=true`，同事务走激活规则并将原项目 `preparing → in_progress`，不得新建交付项目。
- `activateContract`：同事务把关联商机项目从 `preparing` 转 `in_progress`；合同 `matter_id` 为空时回填商机项目事项。重复激活返回现状或按既有乐观锁语义处理，但不得重复审计成功动作。
- 商机关闭后合同创建/激活、费用/差旅/经费/任务新增均被服务端阻断；项目与商机详情响应互相携带对方最小标识，供 18-03 互跳。

## 4. 财务分界与全周期成本

- D4：合同 `active` 是财务 CRM 明细唯一分界；draft/terminated 不给合同前明细，active 后仅该合同链明细。
- 项目核算/相关报表输出补充分段字段（保持既有字段不删）：`presalesCostCents`、`deliveryCostCents`、`totalCostCents`。
- 口径按 arch/13 §5.5：无激活合同（含 lost）有效费用全部售前；有激活合同时按费用明细业务发生日期与合同激活业务日期分段；非商机项目沿用既有项目成本。
- 金额 cents、服务端汇总、台账唯一写入者与核销事务规则不破。

## 5. sysadmin 全局读取与受控纠正基础

- D3：`crm.read`、`fin.read`、项目读取、报表读取/导出对 sysadmin 放行；但不开放口令散列、会话 token、AI key 明文，审计表仍只追加。
- 新增受控纠正端点（如 `admin.correctRecord`）：sysadmin 限定，输入对象类型、id、rowVersion、字段补丁、理由；只允许白名单对象/字段（本棒最小集：线索联系信息、商机基础字段/售前指派、客户基础字段、项目名称/类型/密级、员工部门/岗位/主管）。
- 纠正必须服务端重鉴权、校验状态机与引用、记录 before/after 全快照与理由，使用乐观锁；主管字段走同一成环校验。
- 财务已入账/审批中/审计/会话/口令/密钥不进入白名单；这些对象只能走既有作废、红冲、冲正、停用等语义动作。
- 普通读取不强制逐行审计；导出与纠正必须审计。

## 6. 甘特图服务端口径配合

- `plan.current` 既有 stages/milestones/tasks live 输出可保留给任务列表；新增或调整甘特专用输出，确保前端能只按阶段/里程碑画条，并按节点聚合任务三态计数：done/overdue/delayed。
- 任务三态派生口径：done=已完成；overdue=未完成且截止日早于今天；delayed=当前计划晚于基线或存在已批准延后。不得让任务生成独立甘特时间条数据需求。

## 7. 测试与验收

新增 `server/tests/api/iter18-02.test.ts`（必要时拆分同前缀文件），至少覆盖：

1. 销售 A/B 相互隔离，列表计数、详情、搜索、聚合与 AI/报表相关口径不泄露；销售主管看管理树下级、看不到树外；多级成环被拒。
2. 售前只见指派商机；取消指派后详情同形 404；运营/CEO/partner/sysadmin 全局读；项目写边界不因全局读放大。
3. finance 在合同 draft 时仅 `crm.summary` 汇总，无 CRM 明细；activate 后可见该合同链明细，仍看不到无关商机。
4. 直接建商机：必填项目负责人/幂等键；成功同事务有商机、事项、项目、成员、售前计划/模板任务、档案目录；同键重放不重复取号/立项；同键异载荷 409；失败路径不残留。
5. 线索转化新建与关联既有商机两路径；`sourceLeadId` 与 `converted_*` 一致；重复转化返回现状。
6. markLost 同事务关闭项目并阻断费用/差旅/经费/任务新增；markWon draft 不转交付；activate 后同一项目 `in_progress` 且 project id 不变。
7. 成本分段公式抽查与台账勾稽不重记、不双算。
8. sysadmin 全局读与受控纠正：白名单字段成功、非白名单/财务已入账对象拒绝、理由与前后快照审计完整、rowVersion 冲突 409。
9. 甘特专用输出只返回阶段/里程碑条形节点，任务只聚合三态。
10. 既有 319 用例不回归；受新可见性影响的旧断言按 arch/13 如实更新并说明。
