# 试用验收指南 · 迭代 0–1 已交付能力（供项目方亲自点验）

**入口：** http://localhost:3000 　**口令：** 所有种子账号统一 `Demo@2026`
**环境：** dev 库含合法虚构数据与历轮验收冒烟痕迹；数据皆可再生（`db:seed` 幂等）。

## 账号速查

| 账号 | 角色 | 用它验证什么 |
|---|---|---|
| `partner@lexflow.demo` | 管理层/合伙人 | 立项、审批 key 级延期、驾驶舱全局 |
| `pm@lexflow.demo` | 项目负责人（项目 A/B） | 项目空间八页签、延期申请、质量复核、周报、结项 |
| `member@lexflow.demo` | 项目成员（仅 A） | 越权验证：列表隔离、直链 C 同形 404、文件边界 |
| `huanglei@lexflow.demo` | 质量负责人 | 质量中心视角 |
| `archivist@lexflow.demo` | 档案管理员 | 档案目录/授权审批/审计可见 |
| `sysadmin@lexflow.demo` | 系统管理员 | 审计查阅、无业务内容权 |

## 十五分钟点验脚本（按顺序，★为关键判定）

1. **登录隔离（★）**：member 登录 → 项目索引只显示 1 个项目；pm 登录显示 2 个。未授权项目从不出现，计数也不含。
2. **越权同形（★）**：member 直接访问 `http://localhost:3000/projects/<项目B或C的id>/overview`（id 可从 pm 会话复制）→ 看到「页面不存在」，与访问随机乱写的 id 完全一致——系统不告诉你它存在。
3. **立项（★需 partner）**：`/projects/new` → 选「诉讼案件标准模板」→ 搜客户/级联选事项 → 提交 → 自动进入新项目空间：阶段 4、任务 5、检查项 4、目录 11 全自动生成（项目/计划/任务/档案页签可逐一核对）。
4. **三轨甘特**：进项目 A「计划」页签 → 基线 V1 虚影 vs 当前计划实轨 vs 任务实际点；点「模拟调整」改某任务日期 → 级联推演（不落库）→「按此发起书面延期申请」一键预填。
5. **延期闭环（★）**：pm 对项目 A 发起 key 级延期（原因/影响/恢复措施必填）→ 提交 → partner 到「我的工作台→待审批」通过 → 回计划页看新版本生效、横幅版本号变化。
6. **质量复核分离（★）**：pm 在质量问题把「处理人」和「复核人」设为同一人 → 服务端拒绝（SELF_REVIEW_BLOCKED）；退回必须填理由，事件时间线逐步留痕。
7. **决策闭环**：决策中心新建（可从质量问题带入上下文）→ 项目负责人与质量负责人分别填意见 → 最终决定（选项/理由/条件/检查点四必填）→ 检查点自动生成任务 → 执行验证回写。
8. **周报版本链**：项目 A「周报」→ 生成草稿（内容来自真实任务/质量/决策聚合）→ 确认 → 再改提示产新版本 → 归档后只读且出现在档案中心 06 目录。
9. **档案授权（★）**：archivist 登录 → 审批 member 提交的授权申请 → member 持授权可下载文件；archivist 撤销 → member 立即 404（刷新即失效，全链审计可查）。
10. **统一待办与通知**：工作台五源卡片（任务/审批/复核/周报/授权）处理后即时消失；顶栏铃铛未读角标、单事件不重复轰炸。
11. **审计（★）**：`/audit` —— pm 打开是同形 404；archivist/sysadmin 打开是真实审计表（操作者/动作/时间可筛）。
12. **375px**：浏览器开发者工具切手机视图 —— 登录、列表、工作台均无整页横向滚动。

## 验收反馈方式

点验中发现的任何问题：记「页面/账号/操作/期望 vs 实际」四要素，发给架构会话 → 复现确认后按偏差登记（STATUS.md「偏差与仲裁」）裁定，需要修复的打回对应工单。
