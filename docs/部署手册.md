# LexFlow 部署手册（生产形态）

依据：arch/08 §5（迭代 5 生产构建与部署形态裁定）。适用对象：运维/部署会话。
配套开发环境文档见 `docs/开发环境.md`（开发栈不动，本手册只讲生产栈）。

## 1. 形态总览

三服务（`docker-compose.prod.yml`，compose 项目名 `lexflow-prod`）：

| 服务 | 镜像 | 宿主端口 | 说明 |
|---|---|---|---|
| postgres | postgres:16 | 不发布（仅内部） | 数据卷 `lexflow-prod_pgdata` |
| server | 本地构建 `server/Dockerfile` | 不发布（仅内部） | esbuild 单文件产物 `dist/index.js`（`@lexflow/shared` 打入，pg external）；存储卷 `lexflow-prod_storage` 挂 `/data/storage` |
| web | 本地构建 `app/Dockerfile`（nginx:1.27-alpine） | `${WEB_PORT:-8080}:80` | vite 静态产物 + `/trpc`、`/files`、`/health` 反代 server |

与开发栈端口隔离：开发栈占用 3000（vite）/3001（server）/15432（Postgres，2026-10-26 裁定）；生产栈只发布 8080，两栈可同时运行。

**server 生产构建**（arch/00 §2 v1.1 占位语义兑现）：`npm run build -w @lexflow/server` 由 `tsc --noEmit` 替换为 esbuild 真构建（`server/esbuild.config.mjs`），产物 `server/dist/index.js` + `dist/migrate.js` + `dist/seed.js`；`npm start -w @lexflow/server` = `node dist/index.js`。typecheck 门保留（`tsc --noEmit` 不变）。

**迁移策略（自决并文档化，工单范围 1）**：采用「容器启动时执行」——server 容器 CMD 为 `node dist/migrate.js && node dist/index.js`。`dist/migrate.js` 用 drizzle-orm 自带 migrator 重放镜像内 `/app/drizzle` 迁移文件（不依赖 drizzle-kit，生产镜像不含 devDependencies）；迁移按时间序追加、重放幂等，重复启动无副作用。开发期迁移仍走 `npm run db:migrate`（drizzle-kit）。

## 2. 从零部署

前置：Docker（含 compose 插件）、Git。无需 Node（构建在镜像内完成）。

```bash
git clone <repo> && cd <repo>

# 1) 配置（密钥生成指引见 .env.production.example 内注释；.env.production 不入库）
cp .env.production.example .env.production
#    必填：POSTGRES_PASSWORD、SESSION_SECRET（32 字节随机 hex）

# 2) 构建镜像并起栈（首次构建约 5–10 分钟，取决于网络）
docker compose -f docker-compose.prod.yml --env-file .env.production build
docker compose -f docker-compose.prod.yml --env-file .env.production up -d

# 3) 确认三服务 healthy（server 启动时已自动重放迁移）
docker compose -f docker-compose.prod.yml --env-file .env.production ps

# 4) 可选：灌入演示种子（幂等，可重复执行；口令统一 Demo@2026，仅演示环境使用）
docker compose -f docker-compose.prod.yml --env-file .env.production exec server node dist/seed.js

# 5) 访问 http://localhost:8080
```

> **陷阱**：compose 变量替换默认读根目录 `.env`（开发文件，含开发口令）。生产栈**必须**带 `--env-file .env.production`，否则开发密钥会被注入生产容器。备份/恢复脚本已内置读取 `.env.production`。

## 3. 配置项表

| 键 | 默认 | 说明 |
|---|---|---|
| `POSTGRES_USER` | lexflow | 数据库账号 |
| `POSTGRES_PASSWORD` | （必填，无默认） | 数据库口令，缺失时 compose 拒绝启动 |
| `POSTGRES_DB` | lexflow | 库名 |
| `SESSION_SECRET` | （必填，无默认） | 会话签名密钥，≥16 字符，禁止复用开发值 |
| `SESSION_TTL_HOURS` | 8 | 会话有效期（小时，滑动续期语义见 arch/00 §4 + 迭代 5 工单 02） |
| `FILE_MAX_MB` | 20 | 单文件上传上限；须 ≤ nginx `client_max_body_size`（25m） |
| `WEB_PORT` | 8080 | web 对外端口 |
| `DATABASE_URL` | （compose 组装） | `postgres://<user>:<password>@postgres:5432/<db>`，无需手填 |
| `STORAGE_DIR` | /data/storage（compose 固定） | 文件存储卷内路径 |

服务端完整键校验见 `server/src/env.ts`（zod）；上方未列的键不要加，加了也不会被读取。

## 4. 备份与恢复

**RPO/RTO（开发期目标，arch/08 §5）**：RPO ≤ 24h（每日备份：cron/任务计划每日执行 `bash scripts/backup.sh`）；RTO ≤ 1h（单备份目录一条命令恢复，含校验实测分钟级，见 STATUS 交接记录演练实录）。

```bash
# 备份（产物：backups/<UTC 时间戳>/{db.dump, storage.tar.gz, manifest.txt, sha256-sample.tsv}）
bash scripts/backup.sh

# 恢复（删库重建 + 存储还原 + 校验：台账/审计/文件版本行数比对 manifest，sha256 抽样重算比对）
bash scripts/restore.sh backups/<时间戳> --yes
```

- 校验任一不一致即非零退出并标明差异项；恢复后默认重启 server（断旧连接池，启动迁移幂等），`--no-restart` 可跳过。
- 备份对象库表口径与校验基线随 `manifest.txt` 自描述，恢复跨版本时先比对基线再判读。
- 备份目录 `backups/` 已被 .gitignore 拦挡；生产环境请将其纳入站点级异地副本（本仓库不覆盖真实异地容灾）。

## 5. 升级与迁移流程

```bash
git pull   # 获取新版本（迁移文件只追加不修改）
docker compose -f docker-compose.prod.yml --env-file .env.production build
docker compose -f docker-compose.prod.yml --env-file .env.production up -d
# server 容器重建后启动即自动重放增量迁移；ps 确认 healthy 即完成
```

回滚：代码回退后重 build 重 up；数据库回退只能走 §4 恢复（迁移不逆向，arch 迁移纪律）。

## 6. 故障排查

| 症状 | 排查 |
|---|---|
| `POSTGRES_PASSWORD/SESSION_SECRET 未设置` 报错 | 忘记 `--env-file .env.production`，或文件内该键为空 |
| server 反复重启、日志 migrate 报错 | `docker logs lexflow-prod-server`；多为 DATABASE_URL 不通或迁移文件损坏——核对卷 `lexflow-prod_pgdata` 是否来自旧版本残留（重建：`down -v` 后重起，数据丢失需先有备份） |
| web 502 | server 未 healthy：`docker compose ... ps`；server 日志常见为数据库未就绪（depends_on 已等 healthy，罕见）或迁移失败 |
| 上传 413 | 文件超过 nginx 25m 或 `FILE_MAX_MB`；两者需同时调大并保持 nginx ≥ 服务端 |
| 登录即 401/会话不存 | 确认经 8080 同源访问（不要直打 server 3001）；Cookie 为 HttpOnly+SameSite=Lax，跨端口访问会被拒 |
| 恢复后校验失败 | 看 `[verify]` 行标出的表/文件；行数不符说明备份不完整或库被二次写入，sha256 不符说明存储卷内容被改动 |

容器内直连数据库（只读排查）：`docker exec -it lexflow-prod-postgres psql -U lexflow -d lexflow`。
